# 变体 B · 落地后生长

> **这是变体自己的文档**——**玩法语义与取舍写在这里**，不靠读代码猜。
> 规格口径在 `docs/spec-M4.md` §7.3 · 计划在 `docs/plan-M4.md` §4 的 S4。

## 玩法

**规则集一个字不改**（还是标准玩法）——**玩法差异全来自一个系统**：方块落地后，
**在它上方长出晶体**。

- **晶体在棋盘上的值是 `8`**（普通方块是 `1`）→ **渲染器与录像都分得清**；
- **晶体占着格子**（满行判定是"非 0 即占"）→ **它会挡着那一行消不掉** →
  **玩法上有代价**（不是白送的装饰）；
- **晶体长在锁定格的正上方 → 那一列的上方会被封住** → **那一列从此落不下方块**
  → **玩得越久，可用的列越少** → **这正是"压力递增"落在棋盘上的样子**。

## 生长规则

- **触发**：方块锁定（`piece:locked`）；
- **长在哪**：**锁定方块占据的每一列**，**该列最高的锁定格正上方**，往上取**连续空格**；
- **长几格**：**`1 + 锁定次数 // 4`**——**每 4 次锁定多长一格** → **压力递增**
  （玩得越久，晶体柱越高，腾挪的空间越少）；
- **只写空格**：空格不够就少长，**一格都不够就不写**——**不报错、不硬塞**。

## 写入只走 `writeCells`

**这是外部改变棋盘的唯一合法通道**（FR-11.1 / B-5）。**变体不许自己写棋盘**，
**也不许自己发事件**——**棋盘变化由内核伴随**（N5：状态变更必须由状态所有者伴随）。

## 为什么写入要"待写清单 + 每帧重试"

**内核的写入条件是"不得改到活动方块占据的格子"**（`write_condition_failed`）——
**一批里只要有一格撞上，整批被拒**。而**命令在下一帧才执行**（分发期间派发的
命令进入队列）——**那时活动方块已经是新方块**，甚至被玩家挪过。

**所以**：

1. 算出的目标格**先进待写清单**；
2. **每帧**（`clock:tick`）**重试一次**；
3. **写成功**（`board:changed` 的 cause 是 `writeCells`）**才从清单里划掉**；
4. **重试超过 3 次就放弃那一格**——**宁可少长，不写错**。

**待写清单还有自己的上限**（32 格）——**不靠配额兜底**。

## 变体层的三条硬约束（架构 §2.3 / §4.1 / §7.7）

**变体层禁止 import `kernel` / `bus` / `adapters` / `host`**（**传递依赖也禁**）→
这个变体的三件事分别这样做到：

| 要做的事 | 怎么做到 |
| --- | --- |
| **订阅事件** | **注册表按声明接上**（`on_event` 是入口）——**不用碰总线** |
| **派命令** | **系统层代劳**：`CommandChannel.submit_cells`（`systems/context.py`）——**命令的形状在系统层拼** |
| **看事件负载** | **自己按字段名取**（`_payload_get`）——几行的事，不值得破红线 |

**事件与命令通道的形状由变体自己用 `Protocol` 声明**（`EventLike` /
`CellSubmitter` / `GrowthInstallContext`）——**结构化类型**：真实的信封、真实的
通道、真实的安装上下文都满足它们。

## 变体自己的状态

**盘面镜像**（哪些格非 0）· **待写清单** · **重试计数** · **锁定次数**——
**全在变体自己手里**。**帧末由宿主合并进 `extensions`**（S5 接线）→
**扩展槽放的是摘要**（比如晶体数），**完整状态仍在变体手里**。

## 扩展槽里放什么（`extension_entries`）

**进槽的是"晶体数"，不是晶体位置**：扩展槽**只放标量**（架构 §5.4）→
**一串坐标放不进去** → **位置留在变体自己的盘面镜像里**，**进槽的只是摘要**。

| 东西 | 谁放 | 值 |
| --- | --- | --- |
| `crystalCount` | 变体（裸名） | 已写进棋盘的**晶体格数**（`int`） |
| `growth.crystalCount` | **宿主**（加命名空间） | 上面那条的最终 key |

**key 的命名空间由宿主加**（`<提供者名>.<裸名>`）——**变体只给裸名**：命名空间是
全局责任，**两个变体都叫 `crystalCount` 时不会互相顶掉**。

**扩展槽的变更不另发事件**：它每次都源于一条内核事件（方块锁定 → 内核发
`piece:locked` 与随之的 `board:changed`），**已被那些事件覆盖**；**扩展槽的观测面是
快照**——`snapshot().extensions` 与 `snapshot().extensionFingerprint`。
