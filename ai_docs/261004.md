### 11:15 · `feature/m2-batch-a` · `tests/baseline/contracts_baseline.json` · `tests/baseline/contracts_expected.json`（M2 · S3 契约基线与期望清单显式刷新）

### 11:10 · `feature/m2-batch-a` · `tools/contract_baseline.py` · `tools/_toolkit.py` · `tests/test_contract_baseline_guard.py`（M2 · S2 git 背书守卫）

**发生了什么**：S2 —— 按 ADR-077 加上**第三层防线**：契约基线与期望清单**必须与 `git show HEAD:<路径>` 的内容一致**；工作区改了但没提交 → 红，提交了 → 绿。落笔 `ec730c8`（含 `tests/test_contract_baseline_guard.py` 的 11 条用例）。

**为什么这么写**：前两层守的是**文件内部**（自述块）与**两份文件之间**（逐条相等），它们有同一个盲区——**基线文件本身可以被直接改**，直接编辑基线就能让工具变绿。**第三层把"谁动了这两份文件"交给 git 回答**：git 是这个仓库里唯一**改了就一定留痕**的东西。

**残余上限照旧写实，不美化**：它**仍然挡不住蓄意绕过**——能把两个文件改好再提交的人，也能改好 git 历史。**从"静默绕过"变成"留痕绕过"，不是"防住了"**（ADR-077 的残余上限写进 docstring，也写进用例钉住）。

**三个计划外的必做项**（都是实测撞到才补上的）：① **比对前归一化换行符**——本仓库 `core.autocrlf=true` 且**没有 `.gitattributes`**：`git show` 给的是 blob（LF · 25582 字节），工作区是 CRLF（25952 字节），**逐字节比必然永远红**，守卫会形同虚设（**"永远红"比"没有守卫"更坏**——它让人以为背书在管着）· ② **git 仓库根从"文件所在处"问起**（`git rev-parse --show-toplevel` 的 cwd = 文件的目录），不是从工具自身问起——后者会让"拿仓外的文件来试工具"永远无法验证· ③ **红项带 ASCII 标记 `git-backing`**——Windows 的 GBK 管道会把中文提示打散，测试要断言"这一条红项确实是背书那层报的"，**按字节查标记才稳**。

**被否掉的方案**：① **守卫盯整个工作区**（"有未提交改动就红"）——那会与正常开发流程打架（改声明时基线确实还没刷）；**它守的是那两份文件，不是工作区** · ② **非 git 环境静默跳过**——"守卫在 CI 里没生效"是最坏的结果 · ③ **把守卫写成"挡得住蓄意绕过"**——**它挡不住**，写实比吹大有用 · ④ **逐字节比换行符**——见上，必然永远红。

**反向验证真跑过**（不是只跑一遍绿）：手改基线文件的一条哈希 → 红且点名是基线文件 → 逐字节复原 → 复原后绿；手改期望清单的一条 → 红且点名是期望清单 → 复原；删掉基线文件 → 红 → 复原。**每次都逐字节复原并自检复原结果**——仓库不留脏文件。

**一 · 落盘路径：项目优先，回落 home**（ADR-074）。默认策略 = `<项目根>/.tetris-data/` → 不可写时回落 `~/.tetris/`，**写入只有一处**，**不设环境变量**。

**为什么这么写**：ADR-064 把边界钉死了（路径可注入 · 文件名不带墙钟 · 部件不自己 `open()`），但**明确把"默认路径"留到 M2 定**——这是上游唯一一条点名"留给你"的决策。默认路径要同时满足三件事：**能跑**（不配置也能用）· **能搬**（项目里带着录像一起走）· **不会在只读安装目录上炸**（exe 装到 Program Files 下项目目录不可写）。项目优先 + 回落 home 恰好三条都满足。

**被否掉的方案**：① **只用 `Path.home()`**——项目外的工具与 CI 跑不出一份可随项目搬运的录像 · ② **三平台各配一套规范目录**（`%LOCALAPPDATA%` / `~/Library/Application Support` / `~/.local/share`）——语义最"正确"，但要维护三套分支，**与 ADR-064 否决 platformdirs 的理由同源**（为一个目录引入跨平台分支不划算）· ③ **两处都写**——冗余一份便于携带，但**"读哪一份"立刻成了问题**：同一局录像在两处分叉，**`G2-1` 的 200 局比对会假红**（ADR-064 否决"文件名带时间戳"时用的正是这个理由）· ④ **只认环境变量、不给兜底**——装完第一次跑就报错。

**二 · 回放系统发事件，新开 `replay:` 命名空间**（ADR-075）。5 条事件：`replay:recording-started` / `recording-stopped` / `playback-started` / `playback-stopped` / `frame-stepped`。需求 §8.1 那句「新增事件必须归入既有命名空间」**加一条写明的例外**。

**为什么这么写**：**每个事件类型都是一条永久承诺**（契约 v1 冻结）——新开命名空间是**扩大承诺面**的动作，必须写明理由并改约定。而"录制 / 回放"确实是**独立的能力域**：独立生命周期（开始录制 → 停止录制 → 开始回放 → 停止回放）· 独立产出者（`systems/replay/`）· 独立订阅者（事件流面板 · 日志 · 指标）。**命名空间是"按关注点分组"的，不是"按数量省着用"的**——17 个命名空间不是问题，**把两种时间轴搅在一起才是问题**（`game:` 讲"这一局发生了什么"，`replay:` 讲"这条录像处于什么状态"；FR-7.3 的过滤能力正是按命名空间做的）。

**被否掉的方案**：① **不发事件**——那回放系统就**没法被观测**："这一局录到哪了"没有任何信号源，日志与指标也订阅不到 · ② **塞进 `game:` / `kernel:`**——两种时间轴混在一个命名空间里，**按命名空间过滤时会被搅在一起** · ③ **塞进 `command:`**——`command:` 的语义是"内核收到了一条命令"，回放是宿主侧行为，**产出者对不上** · ④ **新开命名空间但不改约定**——**约定与实现分家**，下一个批次读约定时会以为新开命名空间是违规的，而实现里已经有了。

**三 · NFR-1 的 1000 局回放零差异单独立门 `G2-5`**（ADR-076）。`G2-1` 的 200 局**不加严**。

**为什么这么写**：NFR-1 早就写着「连续 1000 局回放指纹零差异」，但门判据表里只有 `G2-1`（200 局四项全等）与 `G2-4`（千局**模拟**总时长 ≤30 分钟）——**"1000 局回放零差异"这条既不属于前者也不属于后者，一直没有门兜着**（`G2-4` 管的是时长，回放一致性不在它里面）。**一条 NFR 没有门 = 没人验**。分成两道门而不是一道：**门是定位工具**——`G2-1` 验"结果对不对"，`G2-5` 验"多局之下还稳不稳"，两者失败含义不同，**混在一起就定位不了**。

**被否掉的方案**：① **并进 `G2-1` 改成 1000 局**（一道门扛两件事，说不清是哪条挂的）· ② **只把 `G2-1` 改成 1000 局**、不新增门（**顺手改判据比不改更糟**——改过的门会让历史执行记录对不上）· ③ **明确不设门**（NFR-1 就彻底没人验了）。

**四 · 期望源搬到 git 历史背书**（ADR-077）。契约基线与期望清单**必须与 `git show HEAD:<路径>` 逐字节相同**（两条元守卫用例）。

**为什么这么写**：ADR-073 写死的残余上限是「两份文件都在仓内 → **同时改两份仍能骗过工具**」。但那个洞的根子**不是"多了一份文件"，而是"工具拿基线文件的内容当权威"**——**直接编辑基线文件就能让工具变绿**，而没人检查这份编辑是不是走了显式刷新流程。git 是这个仓库里唯一**改了就一定留痕**的东西：**改动进了提交就有人看得见；没进提交，守卫当场报红**。于是骗过工具的门槛从「改两个文件」提到「改两个文件 + 提交 + 让这次提交被人看见」。

**残余上限照旧写实，不美化**：这条守卫**仍然挡不住蓄意绕过**——能把两个文件改好再提交的人，也能改好 git 历史。**ADR-073 那句"同时改两份仍能骗过工具"改写成"能骗过，但一定留痕"**。

**被否掉的方案**：① **把期望清单从 git 历史派生**（基线记一个基准 commit，工具检出那个 commit 重新导入契约模块算期望条目集）——**更硬，但代价大**：派生要在历史提交上执行仓库自己的 Python（worktree + 子进程导入），多一套隔离机制、多一类失败模式，而且**它把期望清单变成机器产物：人看不了、改不了、审不了** · ② **搬进 CI 常量 / 发布产物**（最硬，但**本项目还没有 CI**，为一个基线先搭一套 CI 是本末倒置）· ③ **只加一条"期望清单 == 活契约"的守卫**（已有，挡不住"同时改两份"）· ④ **什么都不做**（ADR-073 明写"更硬的后续选项推到 M2 再议"——**M2 就是那个时机**）。
