## 2026-10-22 20:45 · `AGENTS.md`（Git 提交规范）

**发生了什么**：定下提交标题格式 `【类型：主题】`，类型用**固定的中文表**：`新功能` / `修复` / `文档` / `测试` / `重构` / `性能` / `格式` / `构建` / `持续集成` / `杂务` / `回滚`。破坏性改动在类型后加感叹号（`【新功能!：…】`），标题与正文之间空一行，正文也用中文，一次提交只装一个逻辑改动。

**为什么这么写**：破坏性的判据取"会不会让旧录像、旧存档或既有调用方失效"——这与项目里已有的"版本兼容判据只有一个：这个变更会不会改变重放结果"是同一条判据，两处口径一致，改代码的人不用记第二套标准。类型表必须**封闭**：类型散了就等于没有规范，每个提交标题都成了自由发挥。

**被否掉的方案**：
- 直接用 Conventional Commits 的英文 `feat:` / `fix:`——最初就是这么写的，被否掉了：项目是中文的，类型词也是给人读的，认得英文那套的人自己对得上就行，标题里只写中文。
- 自造一套更口语的类型（比如"改进""优化"）——"优化"分不清是性能还是重构，最后什么改动都能往里塞，等于没有分类。

## 2026-10-22 20:46 · `ai_docs/`

**发生了什么**：建 `ai_docs/` 目录，一周一个文件，命名 `YYMMWW.md`。周的归属按**周一所在的月**算，某月第一个周一落在该月的周是该月第 1 周。当前周是 2026-10-19 起的那一周，属 10 月第 3 周 → `261003.md`。

**为什么这样写**：按周一归属能保证一周永远只属于一个月，不会出现"跨月周"被重复计入或漏计；周次在月内从 1 数，文件名里的月和周一一对应，不用再查表。代价是每月第一周可能不足 7 天（10 月第 1 周只有 10-05 到 10-11，10-01 到 10-04 那几天属于 9 月），这是按周一归属的必然结果，与规则一致，不特殊处理。

**被否掉的方案**：用 ISO 周数（`2026-W43`）。ISO 周跨年时编号会跳（年末年末），且不体现"月内第几周"，与需求里"月的界限以周 1 划分"的描述对不上。

## 2026-10-22 21:39 · `PROGRESS.md`（定位澄清：快照不是流水账）

**发生了什么**：`PROGRESS.md` 原来有一个「已完成」历史表和一份 M0–M4 的完整任务清单，越写越长。用户指出：**这个文件不能做成增量的**——"具体的记录可以在 git 中查，这里内容不要太多"。

> **当前状态快照，不是流水账**：每次工作结束直接改写「当前在攻 / 待办 / 卡点」，**不往这里堆历史条目**——历史记录交给 git。

**被否掉的方案**：
- 保留「已完成」表但只留最近 N 条——"最近 N 条"是个随意的规则，改一次就丢一次历史，还是不如 git。
- 把历史表挪到 `ai_docs/`——`ai_docs/` 是**决策日志**不是**活动流水账**，塞进已完成事项会稀释它"为什么"的定位。
