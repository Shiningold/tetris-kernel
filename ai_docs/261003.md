**并行安全靠三条东西**（写进 plan §1.4）：

1. **文件归属互斥**（§1.4.2）——同一批次内一个文件只能属于一个写手；**包级 `__init__.py` 不属于任何写手**（多个写手都要往里加导出，混写必冲突），导出面由集成者统一收口；`tests/conftest.py` 归 C2、`tests/baseline/**` 归 D2，别的批次不碰。
2. **跨写手的东西先验定签名**（§1.4.4）——并行写手之间**没有协商通道**，一个写手要用另一个写手产出的东西时，签名必须先写死在 plan 里（指纹函数 / 随机源状态 / 内核操作面 / 总线操作面 / 规则集签名五项）。A1 实现偏离签名 → A2 的测试**红**（这正是要的红），修正由集成者裁决，**不许子代理单方面改接口**。
3. **写手只交工作区改动，不自己提交**——git 索引是**单一共享资源**，两个写手并行 `git add` 会互相覆盖；提交由集成者按"一次提交 = 一个阶段"串行切，批次合并用 `--no-ff` 保留批次边界。

**「审查—分支—搭车」工作流**（§1.4.5）：分支命名 `feature/batch-<字母>`，**链式分支点**（批次 N+1 从批次 N 的落笔提交起，不回 master）——这样"审查 A 期间在 B 分支上写 B"成立。搭车边界是**只加不改**：下一批不得动正在被审查的批次已提交的任何文件，也不得改 §1.4.4 的接口约定；A 的修正落地后要 **merge 进 B 分支**再合并 B。审查产物落 `tests/ocr/batch-<字母>-review.md`，**随修复提交入库留证**。

**为什么这么写**：

- **"批次"是排期单位，不是依赖单位**——阶段之间的依赖链（S7 → S8 → S9 → S10 → S12 → S14 → S15 → S16 → S17 → S18）一个字没动，变的只是"几个写手同时开工"。把批次当成依赖单位会误导人以为"同批就是互不依赖"。
- **切批的判据只能是文件归属，不是"看起来像一组"**。S9 / S10 / S12 主题上是一组（命令通道），但它们共用 `kernel/core.py`——强行并行就是三个人改同一个文件，冲突是必然的。所以它们被放进同一批、由**同一个写手串行**做；同批的 S11 才享受并行。**同批 ≠ 并行，同批只是"一起排期"。**
- **每批 3–6 个阶段是目标，不是硬指标**。C / D / E 分别是 2 / 2 / 1 个阶段，规模偏小是**依赖决定的**；为凑数把不相关的阶段塞进同一批，反而制造等待，还撑破"文件归属互斥"这条并行安全前提。**规模服从依赖，不服从数字。**
- **包级 `__init__.py` 归集成者是"纪律"不是"偏好"**——它是本仓"同一形状只允许一处权威定义"的同族问题：两个写手各往 `__init__.py` 加一行导出，就是两份会漂的名单。
- **审查报告仍然不是可靠清单**（沿用昨天定的口径）：修正回合**逐条核实**，成立项在原批次分支上改，**修正提交单独一笔**（`修复：按 batch-a 审查报告修订…`），不与新功能混提。批量并行只会让报告条目更多，核实工作量不会变少。

### 决定要点

- **契约类型声明用规范类型表达式字符串，不用 `typing` 对象**——基线按字段级哈希类型声明，要的是**跨进程稳定**：`hash(int)` 按对象地址算，`typing` 对象的 `repr` 随 Python 版本漂移。字符串还能直接解析、直接写进 JSON。**声明层的类型选型按"将来基线脚本怎么用"定，不按"现在写着顺不顺"定。**（**被否**：`typing` 对象——看着更"类型安全"，实际把基线变成每次跑都不一样的东西。）
- **测试里独立转录需求表做交叉核对，不直接解析 Markdown 表格**——解析文档的测试会把这层交叉核对变成**自证**（声明与它自己解析出来的表相等，等于没比）。代价是转录本身要人工核；已逐条核过。
- **同名字段跨事件必须同类型，例外显式写进测试的例外表**——通用提取代码（回放校验 / 事件完备性检查 / 指标通用提取）按字段名处理负载，同层同名不同型必然踩空。`level`（游戏等级 `int` vs 日志级别 `str`）是跨域同名，**不是缺陷**，写 doc + 例外表即可。
- **负载的 `cause` 与元数据的 `cause` 不改名，用 doc 消歧**——两者**跨层**（负载 vs 元数据）而非同层；元数据的 `cause` 是 ADR-062 定死的三键不能改，为消歧而改名代价大于收益（要动 4 条事件的字段名）。
- **门禁归属做成必填字段 `CommandSpec.lifecycle_gated`**（无默认值，漏表态直接 `TypeError`），三个生命周期原因**由它派生**——推导只挪走"名单会分叉"的风险，挪不走"漏写会静默"的风险（代价是"暂停期间命令照样执行"）。
