# Tetris Kernel

一个以**事件流**为唯一信息载体的俄罗斯方块内核。

不是"做一个俄罗斯方块"，而是"做一个能让俄罗斯方块被反复重构的底座"——任何一次玩法创新（重力翻转、落地后生长、塌方物理），都应当只表现为**新增一个订阅者**，而不需要修改内核。

> **项目状态：M1（可玩）已完成，M2（可观测）进行中。** M1 交付了标准玩法——形状表 · SRS 踢墙表（含 180° 扩展）· T-Spin 五档 · 完整计分表（基础分 + 连击 + B2B + 升级）· 锁定延迟 30 帧 / 重置上限 15 次 · 顶出判定，全部逐条验过，**无头可玩到底**。M2 正在做录像与回放 · 日志与指标 · 事件轨迹导出 · 局面序列化，规格与计划见 [`docs/spec-M2.md`](docs/spec-M2.md) / [`docs/plan-M2.md`](docs/plan-M2.md)。**仍然没有画面**：渲染器与输入适配器属 M3–M4，变体落地属 M4。仓库里的代码目前是**会玩的内核**，不是游戏。

## 解决什么问题

常规俄罗斯方块的写法把规则、输入、渲染、计分耦合在一起。想加一个新机制，就得改动主循环和状态判断，牵一发动全身，而且无法验证这次改动有没有破坏原有手感。

这里的做法是把内核做成**唯一的状态所有者**：输入只能通过命令进来，输出只能通过事件出去，中间的一切都从事件流里长出来。

## 特点

- **事件流是核心资产，不是调试附属品。** 命令的接收 / 接受 / 拒绝三段生命周期、方块操作、消行、计分、成就、每一次取随机数、插件的装卸，全部在流里——连"命令被拒绝"和"每一次取随机数"也都有事件。
- **订阅者地位平等。** 日志、指标、回放、成就、AI、渲染器并列，各自可随时装载或卸载，内核不知道它们存在。
- **渲染器只是又一个订阅者。** 棋盘、幽灵落点、锁定进度、HOLD / NEXT 全部由快照字段驱动；换成终端渲染或网络同步，内核无感。
- **确定性可回放。** 同一份「种子 + 输入序列」在任何设备与负载下重放，逐帧一致。
- **可无头运行。** 不挂渲染与输入也能跑完整局，用于测试、AI 训练与批量模拟。
- **玩法重构不动内核。** 新增一个玩法系统的工作量应当落在"新增文件"级别，而不是"修改主流程"级别。

## 安装

需要 Python 3.12 或更高版本。**本项目只发布在 GitHub，不上 PyPI**——克隆源码后本地安装：

```bash
git clone <仓库地址>
cd tetris-kernel
pip install .
```

不想装、只想玩的，等 M4 之后的 GitHub Release：分窗口版（双击即玩）与控制台版（跑 `sim` / `replay` / `inspect`）两个免安装 exe。

## 使用

```bash
tetris sim          # 批量模拟，输出统计（唯一跑通的子命令）
tetris sim --until game-over   # 跑到顶出就停帧，输出结算八项（M1 · 标准玩法）
tetris play         # 交互式游玩（占位；输入适配器与渲染器属 M3–M4）
tetris replay       # 回放录像（占位；属 M2）
tetris inspect      # 检视事件流（占位；属 M2）
```

也可以用模块入口：

```bash
python -m tetris_kernel
```

> `tetris` **不带子命令会直接报错退出**——子命令必填。只有 `sim` 是真的能跑的；`sim --until game-over` 会用确定性策略打完整局到顶出，并输出结算八项（分数 / 行数 / 方块数 / 连击 / B2B / 等级 / 最终棋盘指纹 / 事件数）。

## 架构

依赖方向恒为 `host > adapters > systems > bus > kernel > rules > contracts`，由 `lint-imports` 持续校验。

```
host        装配层 · 帧循环 · CLI
adapters    输入（DAS/ARR）· 渲染 · 存储
systems     日志 · 指标 · 回放 · 成就 · AI
bus         事件总线 · 订阅 · 优先级 · 环形历史 · 只读视图
kernel      唯一状态所有者 · 命令校验 · 快照 · 可播种随机源
rules       消行判定 · 重力 · 计分 · 边界（四项可插拔）
contracts   事件类型注册表（公共叶子，不 import 任何东西）
variants    变体实现（与 systems 同级）
```

`kernel/` 与 `rules/` 是冻结区——**内核文件差异必须为空**，这是项目唯一不可妥协的核心判据。

## 从源码开发

需要 Python 3.12 或更高版本。

```bash
uv pip install -e .
uv pip install --group dev
```

| 做什么 | 命令 |
| --- | --- |
| 跑测试 | `pytest` |
| Lint / 格式化 | `ruff check .` · `ruff format` |
| 类型检查 | `pyright`（覆盖 `src/` 与 `tools/`） |
| 依赖方向检查 | `lint-imports` |
| 构建 | `uv build`（产出 sdist + wheel） |
