# M5 阶段规格（spec）· Tetris Kernel

> **M5 = 性能回合**：**把 AI 的决策成本降下来，而且决策结果逐条不变。**
>
> 上一版（2026-10-28）· M4 已收官（`323a5ba` 合并 · `cfec469` 回填）· 立项依据见 `docs/plan-M4.md` §4 S12 与 `PROGRESS.md`「卡点」段。

---

## 1. M5 目标与完成判定

### 1.1 一句话目标

**同一个 AI、同一个局面、同一个决策——但决策的成本降一个量级。**

**为什么是"同一个决策"**：性能优化一旦改动了 AI 的选择，它就不再是"提速"，而是"换了一个 AI"——
**录像会分叉、复现口径会变、门判据的期望值要重抄**。所以 M5 的性质是
**等价提速**：**结果逐条不变**，只有代价变。

### 1.2 M5 兑现的三件事

| # | 兑现物 | 落点 |
| --- | --- | --- |
| 1 | **等价提速的搜索实现**（剖面 + 解析式下落 + 路径前缀和 + 增量打分） | `src/tetris_kernel/systems/ai/search.py` |
| 2 | **守住等价的两道牙**（差分测试 + 手抄锚点表） | `tests/test_m5_ai_equivalence.py` · `tests/support/ai_reference.py` |
| 3 | **预算声明订正 + 性能复测记账** | `systems/ai/search.py` 的常量 · `tools/measure_m4_cost.py`（**复用，不改口径**） |

### 1.3 完成判定（DoD 摘要，全表见 §9）

- **决策成本**：AI 决策耗时的 **P99 ≤ 400 μs**（M4 实测 P99 1.82–1.91 ms → **≥ 4.8×**）；
- **等价性**：**随机局面逐条相同** + **手抄锚点表逐条相同**（§7.2 · §7.3）；
- **确定性不变**：决策路径里**没有 `time`**；**候选数与搜索深度仍是固定常量**（M4-D3 延续）；
- **契约面零变化** · **冻结区零变化**；
- **全开档 P99 复测并记账**（§7.6 · **M5 不承诺把它压进 1.6 ms** —— 理由见 §11.2）。

## 2. 术语速查

| 词 | 意思 |
| --- | --- |
| **决策** | AI 为当前方块挑一个落点（`plan_placement` 的一次调用） |
| **候选** | 一个「起手列 × 目标朝向」的落点组合 |
| **剖面** | 一局棋盘的静态统计（每行的填充数 · 每列的有格行 / 顶行 / 洞数） |
| **等价提速** | 结果逐条相同、代价更低的改写 |
| **差分测试** | 新实现与**冻结的参照实现**在大量随机局面上逐条比对 |
| **手抄锚点** | 把若干局面的落点 / 分数 / 命令序列**手抄**进测试的期望值 |

## 3. 现状：钱花在哪（**全部实测 · 不许猜**）

### 3.1 三个数字（M4-S12 实测 · py312 · 同机同时段 · 配对 A/B 三轮）

| 项 | 数 | 出处 |
| --- | --- | --- |
| 全开档逻辑帧 | P50 **617 μs** · P99 **3335 μs**（**超 NFR-2 的 1600 μs**） | `PROGRESS.md` 卡点段 |
| AI 决策耗时 | P50 **≈ 1.55 ms** · P99 **1.82–1.91 ms**（13 次 / 400 帧） | 同上 |
| 默认路径逻辑帧 | P50 545 μs · P99 **1197 μs**（**预算内**） | 同上 |

**独立交叉核对**（另写探针直接量同一个 `plan_placement`）：**不带变体 P50 251 μs · 带变体 B 1260 μs**
→ **变体 B 的晶体把落点扫描变贵了约 5 倍**（晶体填进棋盘 → 落点扫描更深、空洞更多）。

### 3.2 热点（cProfile · 60 次决策 · 现实现）

| 热点 | 占比 | 为什么 |
| --- | --- | --- |
| `_evaluate`（含其内部生成器） | **≈ 40 %** | **每个候选都把整块棋盘复制一遍**（`[list(row) for row in board]`）再全扫两遍 |
| `_fits` | **≈ 20 %** | 方块从 `SPAWN_Y = 0` 落到盘底 → **每个候选逐行试 ≈ 20 次**；64 候选 ≈ **2100 次调用** |
| 其余（枚举 · 命令构造 · 对象分配） | ≈ 40 % | 每个候选都造一遍 `Placement` 与命令序列，**包括最后落败的那些** |

### 3.3 一个必须钉死的口径差（**M5 要订正它**）

- `search.py` 的 docstring 与 `MAX_CANDIDATES = 40` 声明的是「**4 朝向 × 棋盘宽度**」；
- **代码枚举的是 `range(-3, width + 3)` × 4 朝向 = 64 个候选**（**起手列可以落在棋盘外**）；
- 但**落在棋盘外的候选一律被路径检查否掉** → **真正被评估的候选 ≈ 29 个**（四朝向合计）。

→ **声明与实际对不上**（40 vs 64 vs 29）→ **M5 的 S3 订正成真相**（§7.4）。

## 4. 范围边界

### 4.1 M5 范围内

1. **搜索实现的等价提速**（§7.1 的五招）；
2. **守住等价的测试**（差分 + 手抄锚点，§7.2 · §7.3）；
3. **预算声明订正**（§7.4）；
4. **性能复测与记账**（沿用 `tools/measure_m4_cost.py` 的分档口径，§7.6）；
5. **文档与状态同步**（决策记录 · 需求与边界 · PROGRESS · ai_docs · plan §3）。

### 4.2 M5 范围外（**明确不做**）

| 不做 | 为什么 |
| --- | --- |
| **改 AI 的算法**（位棋盘 · 预计算表 · 换启发式） | **会改掉 AI 的选择** → 不再是"提速"（§1.1）→ 录像分叉 · 期望值重抄 |
| **改候选集 / 搜索深度** | 同上；且 M4-D3 把它们定为**固定预算**，改它们是**改玩法**不是改性能 |
| **让 AI 进默认装配** | 破 `G4-9`（零污染）· 事件数基线会变 → **M5 不刷基线** |
| **改 NFR-2 的口径**（把 AI 排除出逻辑帧预算） | NFR-2 只排除渲染 / 落盘 / 导出 / 网络 IO —— **AI 决策在事件分发里发生，它就是逻辑帧的一部分** |
| **把决策分摊到多帧** | M4-D3 明写「**不做帧内增量搜索**」——分帧会让**同一录像在不同机器上分叉** |
| **动冻结区**（`kernel/` · `rules/`） | M5 不需要；`systems/ai/` 本来就不在冻结区 |
| **动 M2 时代的 `measure_frame_cost.py`** | 它的口径已被事件数基线锁住 → **统计口径从它借，不改它** |

### 4.3 M5 期间最容易犯的四条

- **只测"快了"不测"没变"** → **提速把决策改掉了，门判据还全绿**。M5 的**头号门是等价性**（`G5-1`）。
- **差分测试的两份一起改** → **"自证被打破"的老坑**（M1 `G1-1` · M2 · M4 的翻版）→ **必须配手抄锚点表**（§7.3）。
- **拿 M4 收官那次的绝对值当对照** → **跨时段的绝对值不可引用**（M1 的 S14 栽过）→ **同机同时段重测**。
- **测量期间机器上有别的负载** → M4-S12 实测踩过：与 pytest 并发时数字整体抬高（AI 决策从 1.55 ms 虚高到 3.2 ms）→ **空机采样**。

## 7. 行为面规格

### 7.1 等价提速的五招（**原型已实测：1354 μs → 227 μs · 6.0× · 400 局零差异**）

| # | 招 | 原来 | 改成 |
| --- | --- | --- | --- |
| 1 | **剖面一次算好** | 每个候选各算一遍 | 一局算一次（每行填充数 · 每列有格行 / 顶行 / 洞数） |
| 2 | **解析式下落** | 逐行试 `_fits`（≈ 20 次 / 候选） | 每列二分查「下面第一个有格的行」→ **O(cells)** |
| 3 | **路径前缀和** | 每候选逐列扫（≈ 13 步 × 4 格） | 预计算「每列放不放得下」→ 区间判断 **O(1)** |
| 4 | **增量打分** | 每个候选**复制整块棋盘**再全扫 | 只算这块方块**影响的列**（≤ 4 列）与它相邻的对 |
| 5 | **按朝向预计算 + 推迟构造** | 每个候选都造 `Placement` 与命令序列 | 形状信息按朝向预计算；**命令与结果对象只在赢家身上造** |

**等价的四条纪律**（**每一条都要有测试守着**）：
1. **越界的格子不进网格**（形状里**有负偏移的格子** —— J / L / S / Z / T 的某些朝向）；
2. **下落只看出生行以下**（起始位置是否重叠**不检查** —— 与内核的落子口径一致）；
3. **同分先枚举到的赢**（枚举顺序不变 → 平局口径不变）；
4. **每一对相邻列只修正一次**（相邻两列都被影响时，算两遍就偏了）。

### 7.2 参照实现与差分测试（**两份代码的关系要写清楚**）

- `tests/support/ai_reference.py` = **M4 那版实现的冻结副本**（**只用于差分**，不进 `src/`）；
- 差分测试在**固定种子的随机局面**上（含**悬空格子** —— 晶体那种）逐条比对
  **落点 · 分数 · 命令序列**；
- **参照实现不许漂**：它改了 → 差分测试要么红（产品侧也改了）要么绿（产品侧没改）——
  **两种都要在提交里说清楚**，**不许"顺手"改参照**。

### 7.3 手抄锚点表（**防"两份一起改坏"**）

差分测试防不住「**产品实现与参照实现在同一笔提交里一起改**」。所以另有一张
**手抄锚点表**：若干个固定局面的 **落点 / 分数 / 命令序列**，
**从 M4 的实现结果手抄**（不许跑出来贴上去）→ **任何一方被改坏，它都红**。

### 7.4 预算声明订正（`MAX_CANDIDATES`）

- **订正成真相**：声明值 = **实际会被评估的候选数**（枚举数 64 · 真正评估 ≈ 29 —— **两个数都要写清楚**，
  哪个是"预算"、哪个是"枚举范围"要说人话）；
- **候选数与深度仍是固定常量**（M4-D3 延续）——**不许按耗时自适应**。

**证据来源**：M4 代码审查报告 L1（`tests/ocr/m4-review.md` §3·L1）已独立指出
「`MAX_CANDIDATES=40` 从未参与剪枝、实际枚举 64 候选，docstring 与实现不一致」，
M5 直接采信该结论并按上述口径订正（不重复论证）。

### 7.5 确定性纪律（M4-D3 延续 · 不许松）

| 纪律 | 守它的门 |
| --- | --- |
| 决策路径里**没有 `time`** | AST 守卫（`G5-3`） |
| **候选数与深度是固定常量** | 同上 |
| **不按耗时自适应**（不因慢而少搜） | 同上 |
| **不分摊到多帧** | 同上（**帧内增量搜索 = 破 AC-1 / NFR-1**） |

### 7.6 性能复测与记账（**口径沿用 M4-S12 · 不另起一套**）

- 用 `tools/measure_m4_cost.py`（**M5 不改它的口径**）跑同样的**分档**：
  **M3 终局基准 · M4 默认 · 加变体 · 加实时宿主与适配器 · 全开**；
- **同机同时段 · 配对 A/B 交替 3 轮** · **空机采样**；
- 记三笔：**逻辑帧 P50 / P99**（含超预算帧数）· **AI 决策耗时单列** · **渲染与输入单列（不进预算）**；
- **结论写进 `PROGRESS.md` 卡点**（M3 / M4 的同款纪律）。

## 11. 风险与未决

### 11.1 三条会让 M5 返工的风险

1. **"提速"偷偷改了决策** → 差分测试 + 手抄锚点**两道牙**（§7.2 · §7.3）；
2. **性能复测在有负载的机器上跑** → 数字虚高 → **空机采样**（M4-S12 实测踩过）；
3. **参照实现与产品实现一起改** → 差分测试全绿 → **手抄锚点表**兜住。

### 11.2 已知缺口：全开档 P99 离 1.6 ms 还差约 4 %（**如实记**）

- 原型实测：决策 **1354 μs → 227 μs（6.0×）**；
- 由此推算：全开档 P99 ≈ **1.67 ms**（帧自身 ≈ 1.42 ms + 决策 ≈ 0.25 ms）——
  **仍比 NFR-2 的 1.6 ms 高约 4 %**；
- **纯 Python 的等价提速到此基本见底**（再挤要动算法 → **范围外**，§4.2）；
- **三条后续路线**（**都不在 M5 内**，留作后续立项的输入）：
  ① **继续微优化**（预计还能再快 20–30 % → 约 1.6 ms 上下，**边际收益递减**）；
  ② **改算法**（位棋盘 / 预计算表）——**会改掉 AI 的选择**（范围外）；
  ③ **改判据口径**（把 AI 排除出逻辑帧预算）——**要改需求**（NFR-2），**用户拍板**。
