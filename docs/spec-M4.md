> **M4 的一处"格式升版"是预期内的**（不是契约面）：录像格式 `v1 → v2`——变体局的回放校验要比**第五项**（扩展指纹 · G4-2），录像头与结算结构要带上它。**旧 v1 录像必须仍能读**（NFR-9：旧版本数据可被识别并给出明确处理策略），**判据是"会不会改变重放结果"**（架构 §5.5）：v1 录像没有扩展指纹 → 按"无变体"处理，**不是拒绝**。

## 1. M4 目标与完成判定

### 1.1 一句话目标

**换掉整套玩法，内核一个字节都没动；而且人真的能玩、AI 真的能替人玩。** M4 结束时，仓库里有**两个能完整玩完的变体**——**重力可旋转**（走**规则集替换**这条路）与**落地后生长**（走**系统插件 + 受控写入**这条路）——**两个都在 `variants/` 独立目录里，`kernel/` 与 `rules/` 逐文件哈希全等**；有一个**真能按键玩**的实时宿主（终端渲染 + 键盘输入 · DAS/ARR 可调）；有一个**固定搜索预算**的 AI 系统（**与人类走完全相同的命令通道**）；**变体局的录像多比一项**（扩展指纹）且**旧录像仍能读**。

### 1.2 M4 兑现的八件事

| # | 兑现物 | 说明 |
| --- | --- | --- |
| 1 | **变体 A：重力可旋转**（需求 §10「重力可旋转」· 任务号 `M4-A5`） | **规则集替换**路径：`variants/gravity/` 提供一套完整规则集（9 条签名）——**轴是规则集实例的常量**（**内核的 `ctx.axis` 恒为 `down`** · 见 §7.2）· **形状表与踢墙表随轴变换**（`M4-A5`）· **消行口径仍是"满行消"**（**内核的塌落按行** · 详见 §7.2 的口径说明）。**只换规则集，不加任何命令、不改任何既有文件**（M3 的 `switchRuleSet` 机制直接用上——**开局前选轴**） |
| 2 | **变体 B：落地后生长**（需求 §10「落地后生长」· 任务号 `M4-B`） | **系统插件 + 受控写入**路径：`variants/growth/` 是一个订阅 `piece:locked` 的系统，**经 `writeCells` 请求写入**（FR-11.1 · 外部改变棋盘的唯一合法通道）——**变体自己算目标格，内核只校验与落笔** |
| 3 | **变体接线面**（FR-9.2 的延伸） | 宿主侧**变体登记表**（标识 → 规则集 · 附带系统）· `tetris variants` 清单（名字 · 版本 · 规则集 · 附带系统）· **规则集接线表 `RULE_SETS` 扩表**（变体规则集登记进去）——**登记表住在宿主层**（架构 §4.1：唯一知道怎么把部件拼起来的地方是装配层） |
| 4 | **变体状态与扩展槽**（架构 §4.5 · §5.4） | 变体的跨帧状态**由变体自己持有**；帧末**由宿主合并进 `extensions`**（内核的 `_set_extensions` 入口**已在 M0 定型** → **冻结区零改动**）· **`extensionFingerprint` 随变体状态变化而变化**（G4-8） |
| 5 | **实时宿主**（FR-8.x · AC-5） | `host/play.py`：真实时钟 + 固定步长帧循环 + 输入轮询 + 渲染接线 + **降级控制器接进喂帧路径**（ADR-082 · M2 只做控制器没接线）→ **`tetris play` 从占位变真跑** |
| 6 | **渲染器**（FR-8.1 / FR-8.2 · FR-9.4） | `adapters/render/terminal.py`：**纯订阅者**（只消费事件与快照，**不写内核状态**、**不用只读视图通道**）· **全部画面信息由事件与快照推导**（FR-8.2）· **同一内核可同时挂多个渲染器**（终端渲染 + 事件流面板 · FR-9.4） |
| 7 | **输入适配器**（FR-8.3 / FR-8.4 · NFR-8） | `adapters/input/keyboard.py`：原始输入 → 命令，**实现 DAS（延迟自动移位）与 ARR（自动重复速率）且参数可调**· **原始输入与翻译后的意图都发事件**（`input:raw` / `input:intent` · 契约里已登记）· **调整参数不触发状态变更**（NFR-8） |
| 8 | **AI 系统**（FR-8.5 · AC-6） | `systems/ai/`：订阅 `piece:spawned` 与 `clock:tick`，**派发命令**；**与人类走完全相同的命令通道**，内核**不因来源分支**（FR-8.5）· **搜索预算固定**（架构 §7.5：禁止按耗时自适应） |

### 1.3 完成判定（DoD 摘要，全表见 §9）

1. M4 门判据（§9.1）`G4-1`…`G4-9` 全过，每道门有一个可复跑的测试，**每道门都有反向用例**（把实现打坏 → 必须变红）。
2. **至少两个变体可完整游玩，且内核文件差异为空**（`G4-1`）——**由冻结区逐文件哈希 + git 变更清单断言**，不是靠人看一眼。
3. **变体局的回放校验多比一项**：结构指纹之外另比对**扩展指纹**（`G4-2`）；**旧 v1 录像仍能读**（缺第五项 → 按"无变体"处理）。
4. **变体实现落在 `variants/` 独立目录，不碰冻结区**（`G4-6`）——`variants/` 与 `systems/` 同级，**禁 import `kernel` / `bus` / `adapters` / `host`**（架构 §2.3）。
5. **实时宿主可玩**：终端渲染 + 键盘输入 + DAS/ARR 可调（NFR-8），**人按键走的是同一命令通道**（`G4-3` / `G4-4`）。
6. **AI 与人类同通道**（`G4-5` · AC-6）：同一 AI 决策序列与人类手动输入结果一致；**内核不按 `source` 分支**。
7. **契约面只增不改**：事件 **50 条不变** · 命令 **17 条不变** · 拒绝原因 **13 条不变** · 快照 **22 顶层字段不变** · 规则签名 **9 条不变**；**既有键的哈希一个都没变**（`G4-7`）。
8. **冻结区零改动**：`kernel/` + `rules/` **14 个文件逐字未变**——**M4 是第一个不动冻结区的里程碑**。
9. 六条静态检查全绿：`ruff check .` · `ruff format --check .` · `pyright` · `lint-imports` · `pytest` · 事件登记。
10. **范围没越界**：M4 之后清单（需求 §13：联网对战 · 变体脚本化 · 可视化编排 · AI 训练场 · 移动端触控 · 变体市场 · 赛事社区 · 无障碍）**一件都没提前实现**。

## 2. 术语速查

沿用 `docs/需求与边界.md` §4，本文不重新定义。M4 额外需要记住的六个：

| 术语 | 在 M4 的含义 |
| --- | --- |
| **变体（variant）** | **用同一内核跑出不同玩法**的东西。**变体不是"改玩法参数"**，是**换掉规则集 / 挂上插件**——两条路径各有一个样例（变体 A 换规则集 · 变体 B 挂系统） |
| **规则集（rule set）** | **9 条签名的整体替换入口**（`rules/interface.py` 的 `RuleSet`）——**换规则集不用改内核**（FR-4.9）。M4 的变体 A 是**第二套真规则集**（M3 的换规则集用的是**测试注入的替身**） |
| **受控写入（`writeCells`）** | **外部改变棋盘的唯一合法通道**（FR-11.1 · B-5）——变体 B 靠它生长。**变体自己算目标格，内核只校验与落笔** |
| **扩展槽（`extensions`）** | 快照里的**标量扩展位**：**变体跨帧状态由变体自己持有，帧末由宿主合并进来**（架构 §4.5）——**内核不理解内容** |
| **扩展指纹（`extensionFingerprint`）** | 扩展槽的规范化摘要（架构 §5.4）——**变体局回放校验的第五项**（G4-2）。**它与结构指纹（棋盘内容）是两个哈希**，拿错了四项比对会全绿而结果不同 |
| **DAS / ARR** | **延迟自动移位 / 自动重复速率**——手感参数，**归输入适配器**（ADR-044），**内核与规则集都不需要知道**（架构 §7.3 末段） |

## 3. 输入 / 输出与对外接口

### 3.1 输入（M4 接受的东西）

| 输入 | 来源 | 约束 |
| --- | --- | --- |
| 种子 `seed: int` | 构造参数 | 不变 |
| 规则集标识 `rule: str` | 构造参数 / `switchRuleSet` 命令 | **M4 的变体标识要登记在宿主侧**（变体登记表 / `RULE_SETS`）——**内核仍然只认"当前这一套"** |
| 命令 `Command` | `execute(cmd)` | **不变**（17 条）——M4 **不加命令** |
| **原始输入**（按键） | 输入适配器 | **经适配器翻译成命令**；**原始输入与意图都发事件**（FR-8.4） |
| **DAS / ARR 参数** | 命令行 / 运行时 | **可调**；**调整本身不触发状态变更**（NFR-8） |
| **变体标识** | 命令行 / 装配参数 | **必须在宿主侧登记表里**（不在册 → 明确报错，**不拿标准规则集顶替**） |
| **AI 开关与预算** | 命令行 / 装配参数 | **预算固定**（架构 §7.5）——**不许按耗时自适应** |
| 事件流 | 总线分发 | 不变 |

### 3.2 输出（M4 产出的东西）

| 输出 | 形态 | 约束 |
| --- | --- | --- |
| **变体清单** | `tetris variants` 输出 + 可机读结构 | 每个变体：名字 · 版本 · 规则集标识 · 附带系统（FR-9.2 的延伸） |
| **画面** | 终端 ANSI 输出 | **由事件与快照推导**（FR-8.2）· **纯订阅者**（FR-8.1） |
| **输入事件** | `input:raw` / `input:intent` | **契约里已登记** → **M4 不新增事件** |
| **AI 的命令** | 走命令通道 | **与人类同通道**（AC-6）· 来源标记 `source='ai'` **仅作元数据透传** |
| **录像** | JSON Lines | **格式 `v1 → v2`**（头与结算结构多带扩展指纹）· **旧 v1 仍能读** |
| **变体跨帧状态** | 快照的 `extensions` 槽 | **只放标量**（架构 §5.4）· key 唯一 |

### 3.3 对外接口签名（M4 的契约变更）

**M4 不新增任何事件、命令、拒绝原因、快照字段、规则签名**——这是 `G4-7` 的判据。M4 碰契约面的只有两处，**都是新增条目，不是改动**：

| 落点 | 动作 | 性质 |
| --- | --- | --- |
| `contracts/systems.py` 的 `SYSTEM_MANIFESTS` | **新增变体附带系统的条目**（变体 B 的生长系统） | **新增键**（`system/<名字>`）——**不是 major 变更** |
| `systems/replay/format.py` 的录像格式 | **`v1 → v2`**：头与结算结构多带 `extensionFingerprint` | **不在契约基线里**（录像格式不是契约面）· **但要按架构 §5.5 的版本兼容判据处理** |

- **为什么变体系统要进 `SYSTEM_MANIFESTS`**：它是**系统**（订阅事件 + 派发命令 · FR-9.1）——**注册表只认"声明 + 工厂"这个形状**，声明的形状住在公共叶子。**变体系统与普通系统受同一套声明面管** → 依赖图能画出它 → **契约面新增条目**（订阅集改了要有牙，M3 的纪律延续）。
- **为什么录像格式升版不算契约变更**：契约基线哈希的是**声明**（事件负载字段 · 命令参数规格 · 快照字段类型 · 规则签名），**录像格式不在其中**——它是**系统层的文件格式**，版本兼容判据是架构 §5.5 那一条：**"这个变更会不会改变重放结果"**。加第五项**会**改变回放判定的内容（多比一项）→ **升版 + 明确兼容策略**（v1 按"无变体"处理）。
- **`writeCells` 的参数不动**（M4 不给它加条件参数）：FR-11.2「授权粒度可配置（逐格 / 批量 / 条件式）」是 **C 级需求**——**变体自己算好要写哪些格再写**，内核只校验与落笔，**契约面零改动**。**这比给内核加"条件式写入"便宜得多**（加参数 = 改既有键 = major 变更）。

### 3.4 M4 的 major 变更预算（**预算 1 次 · 计划内不动用**）

| # | 变更 | 撞红的东西 | 处置 | 状态 |
| --- | --- | --- | --- | --- |
| **M4-C1** | **预留**：若执行期发现"不改既有键就做不到"，动用一次 | 契约基线里**已有键的哈希变化** | 显式 `--update-baseline --update-expected --reason "<理由>"`，提交信息写明理由 | **未动用**（计划内的 M4 一条契约变更都没有） |

> **M4-C1 是"预算"不是"计划"**——M0–M3 每一批都真的花掉了它（M1 花了三次 · M2 没花 · M3 花了两次），**M4 计划内一条都不花**（§3.3 的两处都是新增条目 / 非契约面）。**预算留着，是给执行期发现的真缺口用的**——**但"预算还在"不等于"可以顺手花"**：动用前必须先回 spec §3.4 落定用途与理由（plan-M3 的 R5 纪律）。
> **M4 若真的动用了 M4-C1，冻结区仍不许动**——两笔预算是**分开的**（契约面 vs 冻结区），**冻结区的那一栏 M4 是空的**。

## 4. 范围边界

### 4.1 M4 范围内

- **变体 A**（`variants/gravity/`）：重力可旋转的完整规则集——9 条签名 · **轴是规则集实例的常量**（`ctx.axis` 恒为 `down` · §7.2）· 形状表与踢墙表随轴变换（`M4-A5`）· **消行口径仍是"满行消"**（§7.2 的口径说明）。
- **变体 B**（`variants/growth/`）：落地后生长——订阅 `piece:locked` → 计算目标格 → 经 `writeCells` 请求写入；**变体跨帧状态自己持有**。
- **变体接线面**（`host/assembly.py` + `host/variants.py`）：变体登记表 · `RULE_SETS` 扩表 · `tetris variants` 清单 · 变体附带系统的装卸接线。
- **契约面扩容**（`contracts/systems.py` + `variants/manifests.py` + `host/discovery.py`）：声明面与依赖图**能容纳变体系统**（扫描根覆盖 `variants/`）——**基线零变化**（变体系统要到 S4 才存在）。
- **扩展槽回写**（宿主 → 内核 `_set_extensions`）：**内核入口 M0 已定型 → 冻结区零改动**。
- **实时宿主**（`host/play.py`）：真实时钟帧循环 · 输入轮询 · 渲染接线 · **降级控制器接进喂帧路径**（ADR-082 的遗留接线）。
- **渲染器**（`adapters/render/terminal.py`）：纯订阅者 · 事件推导画面 · 多渲染器同挂。
- **输入适配器**（`adapters/input/keyboard.py`）：按键 → 命令 · DAS / ARR 可调 · 原始输入与意图都发事件。
- **AI 系统**（`systems/ai/`）：订阅事件 · 派发命令 · 固定搜索预算 · 与人类同通道。
- **录像格式 v2**（`systems/replay/format.py`）：第五项扩展指纹 · 旧 v1 兼容 · `tetris replay` 输出多一项。
- **文档同步**：`docs/plan-M4.md` · `docs/决策记录.md`（M4 的新 ADR）· `docs/需求与边界.md`（§8.1 / §8.2 / §10 / §12）· `PROGRESS.md`。

### 4.2 M4 范围外（**明确不做**）

| 不做的事 | 归谁 | 为什么现在做会坏事 |
| --- | --- | --- |
| **tkinter 图形渲染器** | M4 之后 | 需求 §13 明确"移动端与触控"属之后；**终端渲染器足以兑现 FR-8.1 / FR-8.2**（"渲染器可整体替换"这条正是靠**换渲染器不换内核**兑现的）。**图形渲染器会引入 tkinter 依赖**（架构 §2.3 明确 `kernel` / `bus` / `rules` 禁 tkinter，**适配层可用**——但 M4 不需要） |

| **受控写入的条件式授权**（FR-11.2 的"逐格 / 批量 / 条件式"） | M4 之后 | **C 级需求**；M4 的做法是**变体自己算好格子再写**（§3.3）——**契约面零改动**。真要做条件式授权，是**给 `writeCells` 加参数 = major 变更** |
| **音频 / 音效 / 教学 / 反作弊系统** | M4 之后 | 需求 §10 把这四条标成"M4（机制在 M3）"——**机制 M3 已交**（系统契约 · 注册表 · 自动发现），**内容属之后**。M4 只做 **AI**（用户已拍板进 M4），其余三条不夹带 |
| **M1 遗留的两条真偏离**（0 行 T-Spin 断 B2B 链 · `tspin-mini` 送不到计分） | 后续里程碑 | **修它们要改冻结签名**（`rules/`）——**M4 的冻结区是零改动的**（§4.3 M4-D1）。**要修就得另起一批并显式破例**（M1 的先例） |
| **事件数基线固定场景的扩展**（`piece:lock-delay-reset` 够不着） | 后续 | **那是一次口径变更**（"场景写死"这条准则），该单独立项 |
| **发布 / exe / GitHub 仓库与许可证** | M4 之后 | ADR-008 · 需求 §13 |

### 4.3 M4 期间最容易犯的五条

| 编号 | 红线 | M4 的具体含义 |
| --- | --- | --- |
| **M4-D1** | **冻结区一个字节都不许动** | `kernel/` + `rules/` **14 个文件逐字未变**（`G4-1` / `G4-6`）。**M4 是第一个零破例的里程碑**——变体要什么都得从**规则集替换**或**系统插件**两个口子走（架构 §4.5）。**"改内核让它支持某变体"= 判据作废** |
| **M4-D2** | **渲染器与输入适配器只消费事件** | 渲染器**不得写内核状态**（FR-8.1）· **不得用只读视图通道**（架构 §4.1：渲染器拿不到 `ctx.view()`）· **画面必须能由事件与快照推导**（FR-8.2）——**"渲染器偷偷问内核要棋盘"就是破这条**。输入适配器**只翻译输入成命令**，**不碰内核** |
| **M4-D3** | **AI 的搜索预算固定** | 架构 §7.5：**禁止按耗时自适应 · 禁止帧内增量搜索**。**AI 每帧重算**可以，**重算次数由策略决定，不由耗时决定**。**M4 的 AI 不引入 numpy**（纯 Python 启发式）——**少一个依赖，且天然确定** |
| **M4-D4** | **变体状态经扩展槽回写，不走后门** | 变体跨帧状态**自己持有**；帧末**由宿主合并进 `extensions`**（内核 `_set_extensions` 入口**已在**）——**不许变体自己往内核写、不许宿主直接改内核字段** |
| **M4-D5** | **来源标记只作元数据** | `source='human' / 'ai'` **仅透传**（FR-8.5）——**内核不许因它分支**。**回放期间命令源独占的兜底在宿主层**（架构 §7.1），**不在内核** |

> **M4-D1 是 M4 的立身之本**：M0–M3 各自破过一次冻结区，**M4 若也破，就等于证明"换玩法必须改内核"**——那整个项目的核心价值（需求 §2 · §10）就落空了。**遇到"差一点点就能做"的诱惑时，正确的动作是回到规则集或插件这两个口子找解法。**
> **M4-D2 的判据是"画面能不能只靠事件重建"**：**渲染器自己维护显示模型是允许的**（它不写内核状态），**但那份模型必须完全由事件推导**——**"只有内部才拿得到"的隐含状态 = FR-8.2 破**。

## 6. 契约面规格（M4 必须改的声明与基线）

### 6.1 事件目录（**50 条 · 一条都不新增**）

M4 需要的所有信号**契约里已经登记**：

| 用途 | 事件 | 状态 |
| --- | --- | --- |
| 原始输入 | `input:raw`（负载：动作 · 种类） | **已登记** |
| 翻译后的意图 | `input:intent`（负载：动作 · 命令类型） | **已登记** |
| 渲染节拍 | `render:frame`（负载：帧号 · 耗时微秒） | **已登记** |
| 棋盘变更 | `board:changed`（负载：格子变更 · 成因） | **已登记**（变体 B 写入后由内核发） |
| 消行 / 塌落 | `board:lines-cleared` · `board:collapsed` | **已登记** |
| 方块全生命周期 | `piece:spawned` · `moved` · `rotated` · `kicked` · `locked` · `held` … | **已登记** |
| 局面状态 | `state:changed`（负载：版本 · 规则集 · 相位 · 计分 · 等级 · 连击 · B2B · 活动方块类型 · hold · next） | **已登记** |
| 换规则集 | `kernel:rule-set-changed` | **已登记**（M3 交的） |

- **变体 B 的写入不需要新事件**：`writeCells` 走内核 → 内核照常发 `board:changed`（FR-11.1 明写"照常发出变更事件"）——**变体不自己发事件**（它发事件就是冒充内核）。
- **AI 不发事件**：AI 的产出是**命令**（走通道）——**命令事件由内核发**（`command:received` / `accepted` / `rejected`）。
- **`G4-7` 的判据就是这一节**：**事件目录 50 → 50，零新增**。

### 6.2 命令目录（**17 条 · 一条都不新增**）

M4 用的命令**全是既有的**：

| 用途 | 命令 | 状态 |
| --- | --- | --- |
| 移动 / 旋转 / 落子 | `moveLeft` · `moveRight` · `rotateCW` · `rotateCCW` · `rotate180` · `softDrop` · `hardDrop` · `hold` | **已登记** |
| 受控写入 | `writeCells(cells)` | **已登记**（FR-11.1 · B-5） |
| 生命周期 | `start` · `pause` · `resume` · `reset` | **已登记** |
| 换规则集 | `switchRuleSet(rule)` | **已登记**（M3 交的） |

- **不给 `writeCells` 加参数**（§3.3）：变体自己算目标格 → **契约面零改动**。
- **不加"换轴"命令**：需求 §10 说变体 A「切换经命令通道」，而 M3 已经给了这条通道——**换的是规则集，不是轴**（轴是规则集内部的事，见 §7.2）。**这条空白在 M0 → M3 期间被填掉了**（架构 §7.3 末段）。

### 6.3 快照字段（**22 顶层 + `board` 5 子字段 · 一个都不新增**）

M4 **不加字段、不删字段**。

- **变体状态走 `extensions` 槽**（架构 §5.4）：**只放标量** · key 唯一 · **内核不理解内容**。
- **扩展指纹 `extensionFingerprint` 已在快照里**（M0 定型）——**M4 只是让它真的动起来**（变体状态变 → 指纹变）。
- **`structureFingerprint` 与 `extensionFingerprint` 是两个哈希**（架构 §5.4）——**变体局回放校验要的是后者**（G4-2）。

### 6.4 系统声明面（**扩容到能容纳变体系统 · 既有条目一个都不许改**）

M4 的变体 B（落地后生长）**也是一个系统**——它订阅 `piece:locked`、派发 `writeCells`——
**它受同一套声明面管**（FR-9.1 / FR-9.2）。但它**住在 `variants/growth/`**（G4-6），
**不在 `systems/` 目录里**——于是有一处必须先解决的落差：

| 项 | 内容 | 约束 |
| --- | --- | --- |
| **声明的形状** | 变体系统用**同一套 `SystemManifest`**（名字 · 版本 · 订阅 · 命令 · 产出者 · 落盘需求）——**形状是契约面，不因住在哪一层而变** | 住在 `contracts/systems.py`（公共叶子） |
| **扫描根** | 契约基线的「系统声明」键类**要能扫到 `variants/` 下的声明** | **扫描根扩容必须落在宿主层或工具层**——**`systems/` 不能 import `variants/`**（两者同级 · 架构 §2.3 的横向禁令） |
| **自证** | 变体系统的订阅与命令**同样要指向已登记的类型** | `check_manifest_types()` 同一把尺子 |
| **依赖图** | 变体系统**要出现在依赖图里**（FR-9.2：声明的用处就是生成依赖图） | 宿主层的清单汇总 |

- **为什么变体系统进契约面**：它是**系统**（FR-9.1）——**注册表只认"声明 + 工厂"**。**变体与普通系统受同一套声明面管** → 依赖图能画出它 → **订阅集改了有牙**（M3 的纪律延续）。
- **为什么规则集本身不进契约面**：**契约面描述"对外承诺"**，而变体规则集是**内容**（标准规则集也不在契约基线里——**只有 9 条签名在**）。**规则集换了不改任何既有键。**
- **刷基线的时机跟着声明走（ADR-077）**：**变体系统的声明在 S4 才存在**（变体 B 是 S4 的产物）→ **契约基线的显式刷新区 S4**（**与变体 B 的落地同笔提交** · 带 `--reason`）。**S2 只做扩容，不刷基线**——**提前刷就是刷了不存在的条目**（M2 / M3 的同款纪律：刷基线必须与改动同笔）。

> **这条落差是 M4 执行期发现的**（S1 落笔时）：原计划把"变体系统的契约登记 + 基线刷新"都放在 S2，**但那个时点还没有变体系统**——**刷不出任何新条目**。**处置**：S2 改成**扩容**（让声明面与依赖图能容纳变体系统 · **基线零变化**），**刷基线挪到 S4**（跟着声明一起）。**这比"为了凑一个阶段而提前刷基线"干净**——**没有理由可写的刷新就是橡皮图章**（ADR-019）。

### 6.5 录像格式（`v1 → v2` · **不在契约基线里**）

| 项 | v1 | v2 |
| --- | --- | --- |
| 头 | `version` · `seed` · `rule` · `outcome` | `version="v2"` · `seed` · `rule` · `outcome`（**结算结构多带 `extensionFingerprint`**） |
| 结算结构（四项） | 棋盘指纹 · 分数 · 行数 · 方块数 | **五项**：四项 **+ 扩展指纹** |
| 读入 | 只认 `v1` | **认 `v1` 与 `v2`** |

- **兼容策略（NFR-9 · 架构 §5.5）**：**v1 录像没有扩展指纹 → 按"无变体"处理**（该字段取空槽的摘要）——**不是拒绝**。理由：**v1 录像必然是标准玩法**（M3 之前没有变体）→ **空扩展槽就是正确的答案**。**明确处理 = 不静默损坏**（NFR-9 的原话）：读入时把版本记进结构，**输出里标出"该录像无变体第五项"**。
- **写出时永远是 v2**。
- **回放比对的输出多一项**：标准局第五项恒等（空槽）→ **既有的四项比对语义不变**（AC-1 不受影响）。

### 6.6 基线规则（M4 期间五份基线）

| 基线 | 文件 | M4 的变化 | 处置 |
| --- | --- | --- | --- |
| 契约基线 | `tests/baseline/contracts_baseline.json` | **新增条目**（变体 B 的系统声明 · **S4 刷**）——**不是 major 变更** | 显式 `--update-baseline --reason` + 提交写明理由（**与变体 B 的落地同笔** · ADR-077） |
| 期望清单 | `tests/baseline/contracts_expected.json` | 同上 | 显式 `--update-expected --reason`（**两份要一起刷**） |
| **冻结区哈希** | `tests/baseline/kernel_hashes.json` | **零变化**（M4-D1） | **不刷新**——**M4 是第一个不碰它的里程碑** |
| 事件数基线 | `tests/baseline/frame_events.json` | **零变化**（M4 的新系统不进默认装配） | **不刷新** |
| `bus/` 独立基线 | `tests/baseline/bus_hashes.json` | **零变化**（M4 不改 `bus/`） | **不刷新** |

> **"刷新基线不带 `--reason` 一律拒绝"这条门不放宽**（M0 修好的门，M1 / M2 / M3 沿用，M4 沿用）。

## 7. 行为面规格（变体到底怎么算、实时宿主怎么玩）

> **这一节是 M4 的正题**。M3 交的是"接得上"，**M4 要回答的是"换掉玩法、还能玩、内核没动"**。

### 7.1 变体接线面（FR-9.2 的延伸）

- **变体登记表住在宿主层**（`host/variants.py`）：**标识 → 变体**（规则集 + 附带系统 + 版本）。**为什么不住在 `contracts/`**：`contracts/` 是**公共叶子**（不 import 任何东西）——**变体要 import `rules/` 与 `systems/`**，声明放进公共叶子就等于让公共叶子依赖实现。**规则集接线表 `RULE_SETS` 同理在宿主层**（M3 已定的口径，注释里写着"变体规则集来了就往这张表里加一行"）。
- **变体不自动发现**：M3 的自动发现扫的是 `systems/` 目录，**变体是"玩法"不是"插件"**——把两者混进同一张注册表会让名字空间打架（系统名 vs 变体名）。**变体走显式登记表**（`register_variant()` API + `tetris variants` 清单）——**登记一次，之后命令行按标识选**。
- **不在册就明确报错**：命令行给了没登记的变体 → **明确报错，不拿标准规则集顶替**（M2 的 `replay` 已是这个口径，M4 沿用）——**顶替会让"四项不等 / 五项不等"的报错失去指向性**。
- **`tetris variants` 清单可机读**：名字 · 版本 · 规则集标识 · 附带系统 · 订阅 · 命令（FR-9.2 的同款要求）。
- **进程启动即登记内建变体**（S3 落定 · 口径修订）：**内建变体（变体 A 的三个轴）在命令行进程启动时就接进登记表**（`main()` 里调用 · 幂等）→ **`tetris variants` 的清单 ≡ 登记表**（不多不少）。**这推翻了 S1 的一条判据**——"一个变体都没登记 → 清单是空的"**不再成立**（CLI 进程里内建变体总是已登记）。**换成更强的判据**：**清单 ≡ 登记表**，且**没登记的变体不出现在清单里**（不顶替）。**为什么这么定**：清单与登记表**恒等**比"清单可能为空"更好用——**"清单为空"在有内建变体之后是个没有意义的状态**。

### 7.2 变体 A：重力可旋转（`variants/gravity/` · 规则集替换路径）

**这是 M4 的第一个变体，也是"换规则集"这条路线的第一个真样例**（M3 的换规则集用的是**测试注入的替身**——**替身不进仓**）。

- **换的是整套规则集**：9 条签名**逐条替换**（`rules/interface.py` 的 `RuleSet` 协议）。
- **轴是规则集实例的常量，不是 `ctx` 的字段（执行期对着内核源码核实后的口径 · 落 ADR）**：**内核构造 `RuleContext` 时 `axis` 恒为 `GRAVITY_AXIS`**——`kernel/core.py:114` 定义 `GRAVITY_AXIS = "down"`，`kernel/core.py:2095` 把它写进 `ctx`（**内核不读 `ctx.axis`** · 全库唯一的消费者是 `rules/standard.py`）。**所以"重力方向随 `ctx.axis` 变"在不改内核的前提下不可实现**——`ctx.axis` 永远是 `down`。**口径**：**变体规则集实例自己持一个不可变的轴常量**（`axis="right"` / `"left"` …），`gravity_vector` **忽略 `ctx.axis`**、返回自己那套向量。**实例持不可变常量不违反"规则集无状态"**（架构 §7.3.1 纪律 1 禁的是**可变**状态——存档只存规则集**标识**，`kernel/core.py:545-554`）。
- **重力方向随轴变**：`gravity_vector(ctx)` 按**实例的轴**返回单位向量（`down` → `(0, 1)`；`right` → `(1, 0)` …）。**方向必须是向量不是 dy**（架构 §7.3.1）——**横向重力时 dy = 0**。
- **形状表与踢墙表随轴变换**（`M4-A5` · 架构 §7.3.1 纪律 2 的直接兑现）：`shape_cells(ctx, pieceType, rotation)` 与 `kick_offsets(ctx, pieceType, from, to)` **签名必须带 `ctx`**（参数名即契约 · `signature_mismatches` 逐条比），**但取表按实例的轴**——**内核不做变换，表由规则集整体提供**。
- **表怎么来（这是 M4 的一条设计取舍 · 落 ADR）**：**变体 A 用"轴变换"实现**——形状表由**标准表的坐标按轴做刚体变换**得到（**SRS 的形状在 90°/180° 旋转下有已知等价**），**踢墙偏移按轴映射坐标**（偏移是相对位移，映射是线性的）。**为什么不用全量真值表**：4 个轴 × 7 种方块 × 4 个朝向 × 踢墙 16 种转向 = **全量表是标准表的四倍**，而**变体的踢墙语义本来就是"变体自定义"**（标准 SRS 的踢墙在横向重力下没有物理对应物）。**这条取舍必须写进变体自己的文档**——**"变体 A 的踢墙表是标准偏移的轴映射，不是旋转重力下的真 SRS"**。
- **"切轴"= 换规则集（不是局中切一个轴）**：**内核没有"改轴"这条命令**（`switchRuleSet` 是换**整套规则集**，`kernel/core.py:1116-1137`：**局中禁止换 · 换则重置局面**）→ **开局前选一个轴**，即**登记多份轴不同的规则集实例**（`gravity_down` / `gravity_right` / `gravity_left`），玩家按标识选。**需求 §10 的"切换经命令通道"由 `switchRuleSet` 兑现**（**换的是规则集，不是轴** —— `spec-M4.md` §4.4 已记这条）。**"局中随时转轴"做不到**（要内核给轴开一条可变通道 = 改内核 = M4-D1 破）→ **这条要写进变体自己的文档**。
- **消行口径不变（满行消）**：**内核的塌落是按行的**——`step_clear` 取的是 `group.index` 当行号，`step_collapse` 把被消的行删掉、上面补空行。**横向重力若要"消列"**，内核的塌落就得改成**轴感知**——**那是内核改动 = 冻结区破例 = M4-D1 破**。**所以变体 A 的口径是：重力方向变，消行仍是"填满一行消一行"**。**这条不是偷懒，是把"M4 的内核零改动"当真**——**玩法成立**（方块往右堆、满行照消），**代价写在下面那条**。
- **玩家的操作不随重力轴变**：内核的**软降硬编码向下**（`y + 1`）· **左右移动硬编码 `x ± 1`**——**横向重力下"软降"仍是往下挪一格**。**这两处要随轴变就得改内核** → **不做**。**写进变体自己的文档**：变体 A 的操作是**屏幕方向**的（左右移 · 向下软降），**只有重力与形状表随轴变**。
- **出生位置仍从顶部**：`SPAWN_Y` 是内核常量，出生横坐标按**占位格子的水平跨度居中**（`_spawn_x`）→ 横向重力下方块**从顶部中央出生、然后向右滚**（**玩法自洽**）。
- **横向重力在物理层可行（已核源码）**：内核的**自动下落**（`kernel/core.py:1597-1608`）、**幽灵落点**（`:2024-2037`）与**触地判定**（`:2039-2053`）**全部按向量推进、方向无关**；`_collides`（`:2008-2022`）的**左右是墙** → 横向重力下"墙即地板"成立。**不做 up 轴**：`ay < 0` 被当作"棋盘之上的出生区"（`:2011`）→ 向上重力时方块会飞出棋盘。
- **横向重力的一局很短（K6 · 结构性的）**：横向重力下方块**沿 x 走、y 不变** → 方块**停在顶行**、**堆叠沿 -x 展开** → 棋盘横向只有 **10 格**、一个方块占 3–4 格 → **三四个方块就占满顶行** → 顶出（实测 `gravity-right` 种子 7：**3 个方块 / 451 帧**）。**这是"内核零改动"的结构性代价**，**不是漏做**——**要让方块往屏幕下方堆，得让重力有 y 分量或让出生与堆叠按轴走**（**两件都要改内核**）。**玩家侧的补偿是手动软降**（内核硬编码 `y + 1` → 软降仍往屏幕下方挪）。
- **计分与放置分类**：变体沿用标准口径（T-Spin 三分 + Mini），**分类挂在消行组上**（架构 §7.3.1）——**不给签名加参数**。
- **`G4-1` 的实现体**：**这个变体的全部代码落在新增文件里**，`kernel/` 与 `rules/` **逐文件哈希全等**。

### 7.3 变体 B：落地后生长（`variants/growth/` · 系统插件 + 受控写入路径）

**这是第二个变体，走的是完全不同的那条路**——**规则集一个字不改**（还是标准玩法），**玩法差异来自一个订阅事件的系统**。

- **订阅**：`piece:locked`（方块落地）——**必要时也订阅 `board:changed`**（自己不写棋盘，**只读事件**）。
- **产出**：**经 `writeCells` 请求写入**（FR-11.1）——**这是外部改变棋盘的唯一合法通道**（B-5），**变体不许自己写棋盘**。
- **写入前自己算目标格**：变体持有自己的跨帧状态（已长出的晶体位置），**算出这一帧要写的格子**（只写空格）→ **一次性发一条 `writeCells(cells)`**。**为什么不给内核加"条件式写入"**：那是 major 变更（§3.3），而**变体自己算更便宜**。
- **单帧写入总量有上限**：内核侧的既有上限照旧（超限整批拒绝 · `quota_exceeded`）——**变体不绕过它**（**"变体自己算"不等于"变体可以无限写"**）。
- **写入后的可观测性**：内核照常发 `board:changed`（FR-11.1）→ **渲染器与录像都看得见晶体**——**变体不自己发事件**（§6.1）。
- **变体状态**：晶体位置由变体自己持有；**帧末由宿主合并进 `extensions`**（M4-D4）→ **扩展指纹随晶体生长而变**（G4-8）。

### 7.4 变体状态与扩展槽（架构 §4.5 · §5.4）

- **变体跨帧状态由变体自己持有**（变体对象就是它的状态容器）——**内核不认识变体**。
- **帧末由宿主合并进 `extensions`**：**宿主**问变体"你要往扩展槽里放什么" → 宿主调内核的 `_set_extensions`（**M0 已定型的入口** → **冻结区零改动**）。
- **只放标量**（`int` / `float` / `str` / `bool` / `None`）——**复杂状态由变体自己持有**（架构 §5.4 明写）。变体 B 的晶体位置是**一串坐标** → **不能直接进扩展槽** → **变体 B 要把状态压成一个标量**（如"晶体数"）**才能进扩展槽**；**完整状态仍在变体手里**。**这条要写进变体文档**——**扩展槽不是"变体状态的存档"，它是"变体状态的摘要"**。
- **key 唯一**：宿主合并时校验，重复即结构错误并记错，**不"去重取末值"**（架构 §5.4）。
- **扩展指纹 = 扩展槽的规范化摘要**——**它变 = 变体状态变了**（G4-8）。

### 7.5 实时宿主（FR-8.x · AC-5 · ADR-082 的遗留接线）

- **`host/play.py`**：真实时钟（`RealClock` · **M0 已有**）→ 固定步长累积 → 每步派 `tick` → 推进帧 → 渲染；**输入在轮询间隙读**（不阻塞推进）。
- **降级控制器接进喂帧路径**（ADR-082 · M2 只做了控制器没接线）：**每帧喂一次耗时** → 控制器按 **600 帧滑动窗口 P99** 判档（**判据用 P99 不用均值** · 架构 §7.4）→ 三档顺序固定：**关调试事件 → 降日志级别 → 关历史缓冲**。**不许引入"关闭事件分发"的快速模式**。
- **实时宿主仍然是宿主层**：**它不 import 内核的私有结构**，只经装配层拿到的接口用。
- **`tetris play` 从占位变真跑**（M0 立的占位 · M2 之后只剩它一个）：**占位命令"要能跑、不许报错"**的规矩到 M4 结束为止——**M4 之后 `play` 不再是占位**。
- **无头仍是无头**（AC-5）：**关掉渲染与输入适配器**，`tetris sim` 的行为**一个字节都不变**（M0–M3 的所有无头判据继续成立）。

### 7.6 渲染器（FR-8.1 / FR-8.2 · FR-9.4）

- **纯订阅者**：只消费事件与快照，**不得写状态**（FR-8.1 · M4-D2）；**不得用只读视图通道**（架构 §4.1）——**渲染器拿不到 `ctx.view()`**。
- **画面完全由事件与快照推导**（FR-8.2）：棋盘由 `board:changed` 累积（**初始棋盘是空的**，从空累积是自洽的）· 活动方块由 `piece:spawned` / `moved` / `rotated` / `kicked` 累积 · 计分与相位由 `state:changed` 给出 · **没有"只有内部才拿得到"的信息**。
- **渲染器要能画活动方块的格子**：**它自己按规则集算**——`shape_cells(ctx, pieceType, rotation)` 是**纯函数**（规则集接口），**渲染器带一份规则集**（`adapters > rules` 合法）→ **变体 A 的旋转重力下渲染照样正确**（渲染器跟着换规则集即可）。
- **多渲染器同挂**（FR-9.4）：**同一内核可同时挂终端渲染器与事件流面板**——两者都是订阅者，**互不影响**。
- **渲染不计入逻辑帧预算**（NFR-2 明写：渲染 · 日志落盘 · 指标导出 · 网络 IO **一律不计入**）——**渲染慢不该让内核帧超时**。

### 7.7 输入适配器（FR-8.3 / FR-8.4 · NFR-8）

- **翻译成命令**：按键 → 命令（`moveLeft` / `rotateCW` / `softDrop` / `hardDrop` / `hold` …）。**输入适配器不碰内核**（M4-D2）。
- **DAS / ARR**：**延迟自动移位**（按住方向键的首次重复延迟）与**自动重复速率**（重复间隔）——**参数可调**（FR-8.3）。**手感参数归输入适配器**（ADR-044）——**内核与规则集都不需要知道"多久能再按一次"**（架构 §7.3 末段）。
- **调整参数不触发状态变更**（NFR-8）：改 DAS / ARR **只是改适配器自己的字段**，**不发任何命令、不改内核状态**——**门判据要断言"改参数前后内核逐帧指纹全等"**。
- **原始输入与意图都发事件**（FR-8.4）：`input:raw`（动作 · 种类）· `input:intent`（动作 · 命令类型）——**教学 / 录像 / 反作弊可订阅**。
- **跨平台**：Windows 与 POSIX 的按键读取方式不同 → **适配器内部封掉**（标准库即可，**不引第三方依赖**——环境纪律：少一个依赖没收益）。
- **不引第三方依赖**：**不引 `keyboard` / `pynput` 之类**——它们要编译、要管理员权限、跨平台行为不一致。**标准库 + 平台分支**够用。

### 7.8 AI 系统（FR-8.5 · AC-6 · 架构 §7.5）

- **订阅**：`piece:spawned`（新方块出现）· `clock:tick`（推进时机）· 必要时 `board:changed`（读棋盘）。
- **派发命令**：与人类**完全相同的通道**——**AI 不直接改状态、不走后门**。
- **来源标记只作元数据**（M4-D5）：AI 派的命令带 `source='ai'` → **内核不许因它分支**（FR-8.5）→ **同一 AI 决策序列与人类手动输入结果一致**（AC-6）。
- **搜索预算固定**（M4-D3 · 架构 §7.5）：**固定深度 / 固定候选数**；**禁止按耗时自适应 · 禁止帧内增量搜索**。**AI 每帧重算**可以（重算次数由策略决定，不由耗时决定）。
- **M4 的 AI 不引 numpy**：**纯 Python 启发式**（落点评估 + 固定深度搜索）——**少一个依赖**（numpy 要额外钉版本才能保证"同种子同权重复现"，架构 §7.5）· **且天然确定**。**AI 的自建随机源**若需要，用 `random.Random(seed)` **显式实例化**（架构 §5.3：内核随机源只服务内核，AI 必须自建）。
- **AI 是系统，不是内核的一部分**（M3-D3 的延续）：**它订阅事件 · 派发命令 · 不写棋盘**。

### 7.9 变体局的回放校验（G4-2 · AC-1）

- **第五项 = 扩展指纹**：标准局四项不变 + **变体局多比 `extensionFingerprint`**。**结构指纹不含扩展字段**——**只比四项，变体状态分叉时会全绿**（架构 §5.4 明写）。
- **录像带第五项**（§6.5）：头与结算结构都带 → **录出来就能比**。
- **回放时变体状态怎么回来**：**重放时变体也要装上**（否则扩展槽是空的 → 第五项必然不等）→ **回放宿主按录像头的变体标识装配**。**录像头要记变体标识**——**当前头只有 `rule`（规则集标识）**：**变体标识与规则集标识不是一回事**（变体 B 的规则集就是标准的）→ **录像头要加 `variant` 字段**（v2 的第二处变化）。
- **旧 v1 录像**：没有 `variant` → 按标准规则集 + 无变体处理（§6.5）。

### 7.10 多渲染器与扩展零污染

- **多渲染器同挂**（FR-9.4）见 §7.6。
- **扩展零污染**（M3 的 `G3-6` 在 M4 上的延续）：**关掉 M4 新增的全部系统与适配器（AI · 生长变体 · 渲染器 · 输入适配器）后，内核逐帧指纹与全开时全等**（`G4-9`）——**与 M2 的 `G2-3`、M3 的 `G3-6` 同款**。

### 9.1 M4 门判据（**硬门 · 随 plan-M4.md 落定**）

### 9.4 录像格式升版的处置流程

1. **先定兼容策略**（§6.5）：**v1 按"无变体"处理**，不是拒绝。
2. **改格式代码**（工作区改动，**不提交**）。
3. **写读入兼容用例**（v1 录像样例 → 读入成功 → 四项比对正常 → **输出标明"无变体第五项"**）。
4. **写 v2 往返用例**（录 → 存 → 读 → 五项全等）。
5. **提交**：标题 `新功能!：`（**录像格式变了 = 旧消费方读不了新录像** → 破坏性判据成立）。
6. **反向验证**：喂一份 v1 录像 → **必须能读**；喂一份坏版本号 → **必须明确报错**（不许静默当 v1）。

## 10. 任务分解与执行顺序

> **详细计划在 `docs/plan-M4.md`**（格式照 `docs/plan-M3.md`：阶段 · 任务清单 · 验证方案 · 提交序列）。本文只给**阶段骨架与依赖顺序**。

### 阶段 A：接线面与基线（M4 唯一"不可返工"的部分）

- **A1** 变体接线面（`host/variants.py` · 变体登记表 · `RULE_SETS` 扩表 · `tetris variants` 清单）。
- **A2** **契约面扩容**：让声明面与依赖图**能容纳变体系统**（扫描根覆盖 `variants/` · 变体系统用同一套 `SystemManifest` · 同一把自证的尺子）——**基线零变化**（**变体系统要到 S4 才存在**）。

> **A 阶段是 M4 唯一"不可返工"的部分**——**契约面一改基线就红**，所有下游都要跟着动。**A1 与 A2 之间那段基线必红**（A2 才刷）。

### 阶段 B：两个变体（M4 的正题）

- **B1** **变体 A**（`variants/gravity/`）：重力可旋转的完整规则集 —— **9 条签名** · **轴是规则集实例的常量**（`ctx.axis` 恒为 `down`）· 形状表与踢墙表随轴变换 · **消行口径仍是"满行消"**（内核塌落按行 · 横向"消列"要改内核 → 不做）。
- **B2** **变体 B**（`variants/growth/`）：落地后生长 —— 订阅 `piece:locked` → 算目标格 → 经 `writeCells` 写入 → 状态回写扩展槽。

> **两个变体彼此独立**（一个换规则集、一个挂系统），**可并行**。**两者都必须落在新增文件里**（`G4-1` / `G4-6`）。

### 阶段 C：实时宿主与渲染输入（M4 的"能玩"）

- **C1** **终端渲染器**（`adapters/render/terminal.py`）：纯订阅者 · 事件推导画面。
- **C2** **键盘输入适配器**（`adapters/input/keyboard.py`）：DAS / ARR · 原始输入与意图都发事件。
- **C3** **实时宿主**（`host/play.py`）+ **`tetris play` 真跑** + **降级控制器接进喂帧路径**（ADR-082 遗留）。

> **C 的三个阶段彼此有依赖**（渲染与输入要被宿主接线）→ **一批一写手串行**，或拆成"两个适配器并行 + 宿主串行"。

### 阶段 D：AI 系统与录像升版

- **D1** **AI 系统**（`systems/ai/`）：固定预算 · 同通道 · `source` 只作元数据。
- **D2** **录像格式 v2**（第五项 + 变体标识）+ 旧 v1 兼容 + `tetris replay` 输出多一项。

### 阶段 E：验证与收尾

- **E1** 九道门判据 + 每道门的反向用例 + **元守卫**（门入口不许中途改名）。
- **E2** 性能复测（P50 / P99 · 同机同时段配对 A/B · **AI 决策耗时单独记账**）。
- **E3** 文档同步（决策记录 · 需求与边界 · PROGRESS · ai_docs）。

> **阶段顺序不可乱**：A → B → C → D → E。**A 先行**是因为接线面与契约登记一改就撞红；**B 先行于 C**是因为**渲染器要能画变体 A 的方块**（渲染器带规则集 → 变体 A 的规则集得先在）→ **变体的规则集接口在 B 落地**，C 的渲染器才能接；**D 在 C 之后**是因为录像升版要等"变体局真的能被录能回放"；**E 最后**是因为**门判据要写在实现稳定之后**（先写门再写实现 = 门会被实现反向塑形 · ADR-061 的原话）。

### 11.3 M4 的 ADR

M4 的决策**随做随定**，落定即进 `docs/决策记录.md`（**编号从 ADR-090 起**；`需求与边界.md` §12 的 `ADR-nnn` 取值范围同步扩）。**开工前已知大概率要落的三条**：

| 决策标题 | 决策要点 | 为什么值得记 |
| --- | --- | --- |
| **变体走显式登记表，不进自动发现** | 变体是"玩法"不是"插件"，与系统分表登记 | 混进同一张表会让名字空间打架；**"新增能力 = 新增文件"在变体这条路上不成立**（变体要接线） |
| **变体 A 的形状表与踢墙表用轴变换实现** | 不做 4 倍全量真值表；踢墙偏移按轴映射是变体自定义语义 | **省掉的是机械数据量，省不掉的是"这句话必须写清楚"**——否则后来人会以为它是标准 SRS |
| **AI 不引 numpy，用纯 Python 启发式** | 固定预算的启发式搜索 | **少一个依赖**（numpy 要额外钉版本才敢保证复现）· **天然确定** |
| **变体 A 的消行口径仍是"满行消"，玩家操作不随重力轴变** | §7.2：内核的塌落按行 · 软降与左右移硬编码屏幕方向 → **要让它们随轴变就得改内核 = M4-D1 破** | **这是把"M4 内核零改动"当真的结果**——玩法仍成立（方块往右堆、满行照消），**但"横向重力就该消列"的直觉要写下来**，否则后来人会以为是漏做 |
| **变体 A 的轴绑在规则集实例上，"切轴"= 开局前换规则集** | §7.2：**内核恒传 `ctx.axis="down"`** → 轴只能由**规则集实例的不可变常量**表达 · 换轴走 M3 已有的 `switchRuleSet` | **"重力方向随 `ctx.axis` 变"是规格自己写出来的、不成立的一句**——**执行期对着源码核出来并改口径，比照着规格写出一个假的实现强** |

> **M4 的 major 变更预算（1 次 · M4-C1）写在 §3.4**，不单独立 ADR——它是**预算**不是**决策**（M1 / M2 / M3 同理）。

### 12.2 提交约定（沿用 `AGENTS.md`）

- **标题** `类型：主题`，类型用固定表（**不临时造新类型**）。M4 预计用到：**新功能**（变体 · 渲染器 · 输入适配器 · AI · 实时宿主）· **修复**（审查发现）· **文档**（spec / plan / ADR）· **测试**（门判据与差异断言）· **重构**（接线）· **性能**（复测）· **格式**。
- **破坏性改动**在类型后加感叹号——判据：**会不会让旧录像、旧存档或既有调用方失效**。
  - **录像格式 `v1 → v2`** = **破坏性**（旧消费方读不了新录像）→ `新功能!：`。
  - **契约基线刷新**（A2）= **破坏性**（基线换了 = 比对基准换了）→ `新功能!：`。
  - **变体与宿主接线**（A1）= **破坏性**（宿主装配的既有调用方签名可能变）→ `新功能!：`。
  - **两个变体落地**（B1 / B2）= **不破坏既有调用方**（内核与规则集零改动）→ 不加感叹号。
  - **渲染器 / 输入适配器 / AI 系统**（C / D1）= **新增能力**，既有调用方不变 → 不加感叹号。
- **正文写"改了什么、为什么"**，用中文。
- **一次提交 = 一个逻辑改动**；**格式化与逻辑改动分开提交**；**纯文档提交与代码提交不混提**。
