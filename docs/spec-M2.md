## 1. M2 目标与完成判定

### 1.1 一句话目标

**任意一局可录、可放、可查、可复现。** M2 结束时，仓库里有一套**完整、可验证、不污染内核**的可观测系统：**录像与回放四项全等**（200 局 + 1000 局两档）、**结构化日志**、**按帧采样的指标**、**事件轨迹导出**、**局面序列化与恢复**、**关闭全部可观测系统后内核逐帧一致**——而且**所有落盘都经宿主注入的 sink**，**内核与冻结区一个字节都没动**。

### 1.2 M2 兑现的五件事

| # | 兑现物 | 说明 |
| --- | --- | --- |
| 1 | **录像与回放** | 录像格式 = **种子 + 规则集标识 + 按帧记录的命令序列**（体积远小于逐帧快照）· 录**被接受的**命令且**不可丢**（ADR-030）· 重放后棋盘指纹 / 分数 / 行数 / 方块数**四项全等**（`G2-1` 200 局 · `G2-5` 1000 局零差异）· 支持**中途开始重放 · 逐帧步进 · 暂停** |
| 2 | **日志与指标** | 日志系统是**普通订阅者**（结构化条目 · 分级 · 多输出目标 · 级别映射归系统内，ADR-046）· 指标系统**按事件聚合**并**按帧采样广播**（`metric:sampled`）· 两者都**落盘经 sink**，不自己 `open()`（ADR-064） |
| 3 | **逐帧检视与离线分析** | 只读事件流查看面板（按命名空间过滤 · 暂停）· **完整事件轨迹导出**（供离线分析）· **事件历史作为对比基线**供回归断言 |
| 4 | **持久化与恢复** | 局面**自包含序列化**（版本 · 规则集标识 · 随机源状态 · 棋盘 · 计分）· 恢复后继续推进的结果与未中断时**一致** · 格式**带版本号**且有向前兼容策略 |
| 5 | **可观测不得污染内核** | **关闭全部可观测系统后内核逐帧一致**（`G2-3`）· **抛错订阅者被隔离**（`G2-2`）· 降级三档按 ADR-031 固定顺序 · **冻结区 `kernel/` + `rules/` 一个字节都没动** |

### 1.3 完成判定（DoD 摘要，全表见 §9）

1. M2 门判据（§9.1）`G2-1`…`G2-5` 全过，每道门有一个可复跑的测试，**每道门都有反向用例**（把实现打坏 → 必须变红）。
2. **200 局回放四项全等**（`G2-1`），且**连续 1000 局回放指纹零差异**（`G2-5`）。
3. **关闭全部可观测系统后，内核逐帧指纹与开着时全等**（`G2-3`）——**可观测是订阅者，不是内核的一部分**。
4. **抛错的订阅者被隔离**：内核继续跑，其余订阅者不受影响，错误事件照常发出（`G2-2`）。
5. **千局模拟总时长 ≤ 30 分钟**（`G2-4`），**同机同时段**测得。
6. **契约面只增不改**：事件 44 → **49**（新增 `replay:` 命名空间 5 条）· 命令仍 16 条 · 快照仍 22 顶层字段；**既有键的哈希一个都没变**。
7. **冻结区零改动**：`kernel/` + `rules/` 相对 M1 收官基线**逐文件哈希全等**——M2 **不碰冻结区**。
8. 五条静态检查全绿：`ruff check .` · `ruff format --check .` · `pyright` · `lint-imports` · `pytest`。
9. **范围没越界**：M3–M4 的需求没有在 M2 里提前实现——**热插拔 / AI / 成就 / 渲染器 / 输入适配器 / 变体**仍然不做（§4.2）。

## 2. 术语速查

沿用 `docs/需求与边界.md` §4，本文不重新定义。M2 额外需要记住的五个：

| 术语 | 在 M2 的含义 |
| --- | --- |
| **录像（recording）** | 一局对局的**命令序列**记录（种子 + 规则集标识 + 按帧的命令），**不是**逐帧状态快照（FR-6.1）——体积差一个量级 |
| **重放（playback）** | 把录像里的命令**重新派发**给一个全新的内核实例，跑到同一结束点，再比对四项结果 |
| **sink** | 宿主注入的**可调用对象**（落盘的出口）——ADR-064：路径可注入、部件自己不 `open()` |
| **期望源（expected source）** | 契约基线之外那份"应该是什么样"的期望值的**出处**——M2 起由 **git 历史背书**（ADR-077） |
| **降级三档** | ① 关闭调试事件 → ② 降低日志级别 → ③ 关闭事件历史缓冲（ADR-031 · NFR-2）——**固定顺序 · 带滞回** |

## 3. 输入 / 输出与对外接口

### 3.1 输入（M2 接受的东西）

| 输入 | 来源 | 约束 |
| --- | --- | --- |
| 种子 `seed: int` | 构造参数 | 不变；录像头里记它，**文件名不带它**（ADR-064）——文件名带种子会让"同一局录两次"产生两份文件 |
| 规则集标识 `rule: str` | 构造参数 | 不变；**录像头里记它**（重放要按同一个规则集起内核） |
| 命令 `Command` | `execute(cmd)` | **M2 不新增命令**（16 条封闭，契约 v1 冻结）——重放**复用既有命令** |
| **可观测开关** | 宿主装配参数 | **M2 新增**：关掉全部可观测系统 → 内核逐帧一致（`G2-3`） |
| **sink** | 宿主装配注入 | **M2 新增**：`Callable[[bytes], None]` 一类的落盘出口，**路径由宿主定**（ADR-074） |
| 事件流 | 总线分发 | 不变；M2 的三个系统**都是普通订阅者** |

### 3.2 输出（M2 产出的东西）

| 输出 | 形态 | 约束 |
| --- | --- | --- |
| **录像文件** | 二进制 / JSON 自描述格式 | **带版本号**（FR-10.3）· **头 = 种子 + 规则集标识 + 版本** · 体 = 按帧的命令序列 · **文件名不带墙钟** |
| **存档文件** | 局面自包含数据 | **带版本号** · 含随机源状态 · 恢复后继续推进与未中断时一致 |
| **日志条目** | `log:entry` 事件 | **级别由日志系统按事件类型映射**（ADR-046）——**事件本身不带级别** |
| **指标采样** | `metric:sampled` 事件 | **按帧采样广播** · 聚合口径在指标系统内 |
| **回放事件** | `replay:` 命名空间 5 条 | **新开命名空间**（ADR-075）——需求 §8.1 的约定加一条写明的例外 |
| **事件轨迹导出** | 逐条事件的离线文件 | 只读导出，**不改变事件流** |
| 快照 | 只读 dataclass | **字段集合不变**（22 顶层 + `board` 5 子字段） |

### 3.3 对外接口签名（M2 的契约变更）

M2 **不改任何既有签名**，只**新增一条订阅者侧的接口约定**与**一条宿主装配侧的注入点**：

```python
# contracts —— 公共叶子，不 import 任何东西
EVENT_TYPES: Mapping[str, EventSpec]   # 44 条 → **49 条**（新增 `replay:` 命名空间 5 条）

# 宿主装配侧（M2 新增 · **不属于契约面**，是装配约定）
Sink = Callable[[bytes], None]          # 落盘出口：宿主注入，路径由宿主定（ADR-064 / ADR-074）
```

- **为什么不把 sink 写进契约**：sink 是**宿主的装配约定**，不是内核可见的东西——内核与规则集都不该知道文件在哪。写进 `contracts/` 会让契约面多一个"宿主怎么存文件"的条目，而那件事的归属是 `host/` + `adapters/`。
- **为什么录像格式不进契约**：录像是**落盘产物**，格式归 `adapters/`（存储适配器）+ `systems/replay/`（录什么）两层，**契约面不描述文件长什么样**（契约面描述的是**事件与命令**，不是文件）。
- **`replay:` 事件为什么进契约**：事件是**内核与系统之间的公开信号**，契约面必须登记（§8.1 的目录就是它的登记表）。新开命名空间的决策与理由见 **ADR-075**。

### 3.4 M2 的 major 变更预算（**1 次 · 不到不许用**）

| # | 变更 | 撞红的东西 | 处置 | 状态 |
| --- | --- | --- | --- | --- |
| **M2-C1** | **（预留 · 用途待落定）** | 契约基线里**已有键的哈希变化** | 显式 `--update-baseline --reason "<理由>"`，提交信息写明理由 | **未动用** |

> **M2 计划内的事件变更不是 major 变更**：新增 `replay:` 命名空间的 5 条事件 = **新增键**——架构 §4.4 明确"允许新增键（新增快照字段 / 事件 / 命令是正常成长）"，**不撞红**。S3 要做的是一次**显式刷新**（带 `--reason`），理由写"新增 replay: 命名空间的事件声明"，**但它不是 major 变更**。
> **M2-C1 为什么预留而不是写死用途**：**随做随定**——M2 最大的不确定性在 S5（总线增强）可能牵出既有键的改动。真撞上了就在那一步落定用途并写明理由；**没撞上就让它一直空着**（M1 的三次一次都不许多，M2 的这一次同理）。
> **"刷新基线不带 `--reason` 一律拒绝"这条门不放宽**（M0 修好的门，M1 沿用，M2 沿用）。

## 4. 范围边界

### 4.1 M2 范围内

- **`replay:` 命名空间的 5 条事件声明**（`contracts/events.py`）+ 需求 §8.1 事件目录登记 + §8.1 约定的写明例外（**只增不改**）。
- **契约基线与期望清单的显式刷新**（新增键）+ **期望源的 git 背书加固**（两条元守卫，ADR-077）。
- **存储适配器**（`adapters/`）：把宿主注入的 sink 落成文件 · **默认路径策略**（项目优先 → 回落 home，ADR-074）· 目录自建 · **不静默失败**。
- **总线增强**（`bus/`）：**中间件** · **历史查询** · **计数**（ADR-019 明写"M2 要给总线加中间件、历史查询、计数"）+ **`bus/` 独立基线**（ADR-019："等 M2 总线封板后再启用"）。
- **日志系统**（`systems/log/`）：普通订阅者 · 结构化条目 · 分级 · 多输出目标 · **级别映射在本系统内**（ADR-046）。
- **指标系统**（`systems/metrics/`）：按事件聚合 · 按帧采样广播（`metric:sampled`）· 落盘经 sink。
- **回放系统**（`systems/replay/`）：**录制**（录被接受的命令 · 不可丢 · ADR-030）· **重放** · **中途开始** · **逐帧步进** · **暂停** · 回放事件（ADR-075）。
- **局面序列化与恢复**（FR-10.1 / 10.2 / 10.3）：自包含数据 · 恢复后继续推进一致 · 版本号与兼容策略。
- **事件轨迹导出**（FR-7.4）· **事件流查看面板**（FR-7.3 · 按命名空间过滤与暂停）。
- **降级控制器**（X-3 · ADR-031 · NFR-2）：三档固定顺序 + 滞回。
- **宿主侧**：`sim` 增录像 / 重放 / 导出模式；**`replay` 与 `inspect` 两个占位子命令兑现**（`play` 仍占位）。
- **文档同步**：`docs/plan-M2.md` · `docs/决策记录.md`（M2 的新 ADR）· `docs/需求与边界.md`（§8.1 与 §12）· `PROGRESS.md`。

| --- | --- | --- |

| **插件热插拔与卸载** | M3 | AC-8 是 M3 判据。**M2 的日志系统**是一个普通订阅者，**但 M2 不支持运行中卸载它**——M2 交付的是"装上就一直在"，M3 才交付"运行中摘掉" |
| **AI 系统** | M3 | ADR-028 的固定搜索预算纪律跟 AI 一起落地。M2 的"多局回放"用**确定性参考策略**（M1 已交付的那套），不进 `systems/ai/` |
| **成就系统** | M3 | `systems/achievements/` 仍是空壳。**M2 不碰** |
| **变体实现** | M4 | G4-1 判的是 M4 落地变体时内核差异为空 |
| **运行期换规则集 / 换轴命令** | M3 | ADR-061 已排到 M3。M2 的录像**记录**规则集标识，但**不提供换规则集的能力** |
| **事件流查看面板的 GUI** | M3–M4 | M2 的"面板"是**只读的命令行视图**（按命名空间过滤 · 暂停）——FR-7.3 自己写的是"（开发态）"。**GUI 属渲染器那一档** |
| **时间旅行（按全局事件序号查）** | M2 的一部分但**不完整** | M2-18 在 §12 的任务表里。**M2 只做"逐帧步进"**（FR-6.3 明写的那部分）；**按事件序号跳转**需要事件历史的随机访问索引——**M2 的总线历史是环形缓冲**（M0 的既有形态），**随机访问属 M2 之后**。**这一条要写进 §11.2 的已知取舍**，不许默默不做 |
| **M1 遗留的三条真偏离** | 后续里程碑 | 0 行 T-Spin 断 B2B 链 · `tspin-mini` 送不到计分（两条**同根因**，要改冻结签名）· 事件数基线够不着 `piece:lock-delay-reset`（要改基线场景口径）。**它们不阻塞 M2**（PROGRESS 已记） |
| **发布 / exe / GitHub 仓库与许可证** | M4 之后 | ADR-008：发布时点整体推后。**但 M2 的落盘路径策略要为将来装到只读目录做准备**（ADR-074） |

### 4.3 M2 期间最容易犯的五条

| 编号 | 红线 | M2 的具体含义 |
| --- | --- | --- |
| **M2-D1** | **可观测系统不得写状态** | 日志 / 指标 / 回放**三个系统都是订阅者**：只消费事件，**不写棋盘、不写分数、不改活动方块**。它们唯一的"输出"是**事件与文件**。**`G2-3` 就是这条红线的门**——关掉全部可观测系统，内核逐帧一致 |
| **M2-D2** | **落盘只走 sink** | **任何部件都不许自己 `open()` / `Path.home()`**（ADR-064）。路径策略在**宿主**（ADR-074）。**`systems/` 连 import `adapters/` 都不行**（依赖方向，lint-imports 守着）——回放系统**知道有 sink，不知道路径** |
| **M2-D3** | **录像只录被接受的命令，且不可丢** | 录 `command:accepted`（不是 `command:received`——校验前的命令含被拒的，重放时状态未必相同）· **不可丢**靠**没有队列**保证（ADR-030）：内存 list 累积，局末或周期点一次性落盘。**有界可丢队列被明确否决过**——丢一条命令 = 录像静默分叉 = `G2-1` / `G2-5` 全废 |
| **M2-D4** | **契约面只增不改** | M2 只**新增** `replay:` 的 5 条事件 · **不改任何既有键的类型串** · 命令与快照字段**一个不加**。真要改既有键 → **走 M2-C1**，写明理由，**不许顺手改** |
| **M2-D5** | **冻结区一个字节都不动** | `kernel/` + `rules/` **M2 全程只读**。M2 的可观测能力**全部在系统层 / 总线 / 存储 / 宿主**——**这正是"底座而非游戏"的兑现点**。冻结区基线**M2 不刷新**（没有理由可写） |

## 6. 契约面规格（M2 必须改的声明与基线）

### 6.1 事件目录（44 → **49** 条 · **只增不改**）

M2 需要的信号里，**绝大部分契约里已经登记**：日志（`log:entry`）· 指标（`metric:sampled`）· 渲染（`render:frame`）· 命令（`command:accepted`）· 种子与规则集标识（`game:created`）· 帧推进（`clock:tick`）· 错误隔离（`kernel:error`）· 插件（`kernel:system:installed` / `removed`，**M3 用**）。

**唯一的开口是回放系统自己**——它有独立的生命周期与产出者，**新开一个 `replay:` 命名空间**（**ADR-075**）：

| 命名空间 | 事件 | 产出者 | 触发时机 | 关键负载 |
| --- | --- | --- | --- | --- |
| replay | `replay:recording-started` | `systems/replay/` | 开始录制 | 种子、规则集标识 |
| replay | `replay:recording-stopped` | `systems/replay/` | 停止录制 | 命令数、帧数 |
| replay | `replay:playback-started` | `systems/replay/` | 开始重放 | 种子、规则集标识、命令数 |
| replay | `replay:playback-stopped` | `systems/replay/` | 重放结束 | 四项比对结果（指纹 / 分数 / 行数 / 方块数） |
| replay | `replay:frame-stepped` | `systems/replay/` | 重放逐帧步进 | 帧号、该帧命令数 |

**需求 §8.1 的约定要改**：原文「新增事件必须登记到本表并**归入既有命名空间**」——M2 加一条**写明的例外**：

> **例外（M2 · ADR-075）**：`replay:` 是 M2 新开的命名空间。理由见 ADR-075——**"录制 / 回放"是独立的能力域**（独立生命周期 · 独立产出者 · 独立订阅者），**两种时间轴混在一个命名空间里，按命名空间过滤时会被搅在一起**（而 FR-7.3 的过滤能力正是按命名空间做的）。**命名空间是"按关注点分组"的，不是"按数量省着用"的。**

> **为什么这条值得改约定而不是默默做**：**每个事件类型都是一条永久承诺**（契约 v1 冻结）。新开命名空间是**扩大承诺面**的动作——它必须**写明理由并改约定**，否则下一个批次读约定时会以为新开命名空间是违规的，而实现里已经有了。**约定与实现分家，两边都不可信。**

**其余命名空间 M2 一个不动**（命令、game、clock、piece、board、score、progress、state、render、log、metric、achievement、rng、queue、input、kernel）。

### 6.2 命令目录（16 条 · **M2 不新增**）

M2 用到的命令全部已在册：`start` / `pause` / `resume` / `reset` / `tick` / `moveLeft` / `moveRight` / `softDrop` / `hardDrop` / `rotateCW` / `rotateCCW` / `rotate180` / `hold` / `setLevel`。

- **重放复用既有命令**：录像里存的就是这些命令的**类型与参数**，重放时原样派发。
- **逐帧步进用 `tick`**：一帧 = 一条 `tick`；**暂停用 `pause` / `resume`**——**不为"步进"新增一条命令**（那会让命令目录多一条永久承诺，而 `tick` 已经能做这件事）。
- **M2 不实现 `writeCells`**：受控写入是变体的通道（FR-11.1），**M4 才用**。

### 6.3 快照字段（22 顶层 + `board` 5 子字段 · **字段集合不变**）

- **存档需要的东西契约里已经全有**：版本（`version`）· 规则集标识（`rule`）· 随机源状态（`rngState`，**它是存档用、不进常规只读视图**——`contracts/snapshot.py` 的 docstring 已写明）· 棋盘（`board`）· 计分（`score` / `lines` / `combo` / `b2b` / `level`）· 活动方块（`active`）· 计时器（`lockTimer` / `gravityTimer`）。

## 7. 行为面规格（可观测到底怎么算）

> **这一节是 M2 的正题**。M0 的总线是"发布 / 订阅 / 环形历史"，M1 的玩法是"算得对"，**M2 要回答的是"看得见、并且看得准"**。

### 7.1 录像格式（FR-6.1）

- **三件套**：**种子 + 规则集标识 + 按帧记录的命令序列**。
- **为什么记命令而不是记状态**：逐帧状态快照的体积是 O(帧数 × 棋盘面积)，命令序列是 O(帧数 × 命令数)——**差一个量级以上**（FR-6.1 明写"体积应远小于逐帧状态快照"）。
- **为什么这是重放的前提**：内核的确定性来自"同种子 + 同命令序列 → 逐帧结果一致"（NFR-1）。**命令序列 + 种子就是完整的输入**——重放不需要存任何状态。
- **每条命令记什么**：命令类型 · 参数（`args`）· **该命令所在帧号**。帧号用于**中途开始**与**逐帧步进**（§7.4），不参与确定性。
- **参数规格**（需求 §8.2 的既有纪律）：`args` 只含 JSON 标量与元组，**禁止浮点**——录像格式沿用。

### 7.2 录制（**不可丢** · ADR-030 · M2-D3）

- **录什么**：`command:accepted` 事件里的命令（**校验后被接受的**）。**不录 `command:received`**——校验前的命令含**被拒的**，重放时内核状态未必相同，同一条命令可能被接受也可能被拒 → **录像会分叉**。
- **不可丢**：**内存 list 累积**，**局末或周期点一次性交出去**。
  - **否决过"有界可丢队列"**（ADR-030）——**丢一条命令 = 录像静默分叉**，`G2-1` / `G2-5` 全废。
  - **"不可丢"靠没有队列保证，不靠队列策略**——**队列本身就是丢的来源**。
- **周期点是什么**：局末或**固定帧间隔**（让长局的内存占用有上界）。**周期点的定义要写死**（不写死 = 各处实现不一致 = 录像格式不一致）。
- **重放时怎么用**：命令序列**原样派发**给一个**全新的内核实例**（同种子 · 同规则集）。

### 7.3 重放与四项比对（FR-6.2 · `G2-1` · `G2-5`）

**四项**：**棋盘指纹 · 分数 · 行数 · 方块数**（AC-1）。

- **重放的判定方式**：录一局 → 重放 → 跑到同一结束点 → **四项逐条相等**。
- **"逐条相等"不是"最终态差不多"**：四项**各自**相等才算过；**指纹是棋盘内容的哈希**（不是棋盘本身）。
- **两档门**（ADR-076）：
  - `G2-1`：**200 局**不同种子，各局四项全等。
  - `G2-5`：**连续 1000 局**回放**指纹零差异**（NFR-1 的兑现——这条此前**没有门兜着**）。
  - **两档跑的是同一批局**（1000 局那一批的前 200 局就是 `G2-1` 那批）——**同机同时段一起跑**，**不许互相引用对方的数字当结论**（跨时段的绝对值不可引用，见 plan-M1 §7 R10）。
- **重放不是"再跑一遍"**：重放**不重新决策**，只重放录下来的命令——所以它测的是**"录像能不能还原这一局"**，不是"策略好不好"。

### 7.4 中途开始 · 逐帧步进 · 暂停（FR-6.3）

- **中途开始**：从录像的**第 N 帧**开始重放——**重放内核先跑到第 N 帧，再开始派发第 N 帧起的命令**。
  - **实现的两种做法**（**M2 选前者**）：① **从头重放、到第 N 帧再进入步进模式**（**状态自然正确**，代价是慢）· ② **用存档跳过去**（快，但要保证存档与重放的状态完全一致——**FR-10.2 的存档恢复一致性与它绑定**）。
  - **M2 选 ①**：慢但**没有第二条正确性路径**。② 的"快"是**用一条新的正确性赌注换的**，而 FR-10.2 的存档一致性本来就是 M2 要验的东西——**不要在同一批次里让两条互相依赖的路径互相验证**。
- **逐帧步进**：一次走一帧（一条 `tick`），每步发 `replay:frame-stepped`。
- **暂停**：用既有的 `pause` / `resume` 命令——**不为步进新增命令**（§6.2）。
- **"逐帧检视"的含义**：**观察者能在任意一帧停住，看当时的棋盘与事件**——M2 交付的是**命令行视图**（§4.2 的范围外说明）。

### 7.5 局面序列化与恢复（FR-10.1 · FR-10.2 · FR-10.3）

- **自包含**（FR-10.1）：版本 · 规则集标识 · **随机源状态** · 棋盘 · 计分 · 计时器 · 活动方块。
- **恢复后继续推进的结果与未中断时一致**（FR-10.2）——**这是硬判据**：恢复后跑 N 帧，与"不中断直接跑 N 帧"的逐帧指纹全等。
- **随机源状态为什么必须在存档里**：不存 → 恢复后的随机序列从头开始 → **后续每一帧都可能不同**。`rngState` **在快照里**（`contracts/snapshot.py` 已登记，**且明确是"存档用"**）。
- **版本号与兼容策略**（FR-10.3 · NFR-9）：**旧版本数据可被识别并给出明确处理策略，而非静默损坏**——不认识的头 → **明确报错**，**不猜、不静默降级**。

### 7.6 日志系统（FR-7.1 · ADR-046）

- **普通订阅者**：只消费事件，不写状态（M2-D1）。
- **结构化条目**：级别 · 频道 · 消息 · 数据——`log:entry` 的负载**契约里已登记**。
- **级别映射在本系统内**（ADR-046）：**事件不自带级别**——同一事件排障时是 trace、演示时可能是 info。**事件不该知道自己有多重要。**
- **多输出目标**：控制台 · 文件（经 sink）· 内存——**输出目标可插拔**。
- **不新增契约条目**：`log:entry` 已在 44 条目录里。

### 7.7 指标系统（FR-7.2）

- **按事件聚合统计**：各类消行次数 · 连击峰值 · 操作频次 · 每块得分等。
- **按帧采样广播**：`metric:sampled`（负载 = 全部聚合指标）——**契约里已登记**。
- **聚合口径写在指标系统内**——**不塞进事件**：事件只说"发生了什么"，"怎么统计"是消费方的事（与 ADR-046 同一把尺子）。
- **落盘经 sink**（M2-D2）。
- **M2-9（空洞率统计）**在 §12 的任务表里——**它依赖 step 化的帧推进**，M2 的帧模型已经是 step 化，所以这一条**M2 可做**（详见 `PROGRESS.md` 的任务表）。

### 7.8 事件轨迹导出与事件流查看面板（FR-7.4 · FR-7.3）

- **导出完整事件轨迹**（FR-7.4）：逐条事件的离线文件，供离线分析。**只读导出，不改变事件流**。
- **事件历史作为对比基线**（FR-6.4）：把事件历史（而非命令）作为回归断言的基线——**这是 M2 给 M3 / M4 送的工具**。
- **事件流查看面板**（FR-7.3）：**只读** · 可按**命名空间过滤** · 可**暂停**。**M2 交付命令行视图**（FR-7.3 自己写的是"（开发态）"）。
  - **过滤为什么按命名空间**：FR-3.2 明写"事件按命名空间划分，命名可枚举且有文档"——**命名空间过滤是契约给的能力**。
  - **ADR-075 的新命名空间在这里兑现价值**：`replay:` 与 `game:` 分开，**过滤时不会搅在一起**。

### 7.9 降级三档（X-3 · ADR-031 · NFR-2）

**固定顺序 · 带滞回**：

| 档 | 动作 | 触发 |
| --- | --- | --- |
| ① | 关闭调试事件 | 手动只开放第 ① 档 |
| ② | 降低日志级别 | **自动**：P99 > **1.6ms**（**600 帧窗口**）降档 |
| ③ | 关闭事件历史缓冲 | **自动**：P99 < **1.0ms** 持续 **1800 帧**升档 |

- **三档都不伤指标系统**；**关事件分发被否决**（会破坏事件完备性）。
- **第 ③ 档不暴露给用户手关**——用户手关会让时间旅行调试"看起来坏了"。
- **判据用 P99 不用均值**（ADR-031）。
- **预算 1.6ms 来自 NFR-2**（60fps 下单帧逻辑 ≤ 帧步长的 10%）——**这是工程预算，不是某台机的测量值**；**测量口径的纪律见 plan-M1 §7 R10**（跨时段的绝对值不可引用）。

### 7.10 落盘路径策略（**项目优先 · 回落 home** · ADR-074）

- **项目下建 `<项目根>/.tetris-data/`**；**不可写时回落 `~/.tetris/`**。
- **写入只有一处**——不在两处各写一份（ADR-074 的硬要求）。
- **目录由程序自己创建**，已存在则复用；**回落要能被用户看见**，不静默失败。
- **不设环境变量**。
- **策略住在宿主装配层**（`host/`）——`systems/` 不许知道路径（M2-D2）。
- **`.tetris-data/` 必须进 `.gitignore`**。
- **测试一律注入 `tmp_path`**；默认路径策略**由一条独立用例覆盖**。

### 7.11 总线增强（中间件 · 历史查询 · 计数 · ADR-019）

- **中间件**：事件分发链上可插入的横切处理（**不改变事件内容**）。
- **历史查询**：环形历史（M0 的既有形态）之外的**查询能力**——M2 提供**按条件检索**；**按事件序号随机访问**属 M2 之后（§4.2 的范围外说明）。
- **计数**：按命名空间 / 按事件类型的计数——**供指标系统与事件完备性判据用**。
- **`bus/` 独立基线**：**总线封板后生成一次**（ADR-019）——**批批刷新会变成橡皮图章**。
- **`bus/` 不在冻结区**（ADR-019）——M2 改它**不需要 major 变更**，但**它是 M3 / M4 的比对基准之一**，所以封板时要刷一次并写明理由。

## 9. 验收标准

### 9.1 M2 门判据（**硬门 · 随 plan-M2.md 落定**）

| 编号 | 判据 | 判定方式 |
| --- | --- | --- |
| `G2-1` | **200 局回放四项全等** | 录 200 局不同种子的对局 → 逐局重放 → **棋盘指纹 · 分数 · 行数 · 方块数**四项**逐条相等**（AC-1） |
| `G2-2` | **抛错订阅者被隔离** | 注入一个必然抛错的订阅者 → 内核**继续正常运行** · 其余订阅者**不受影响** · **错误事件照常发出**（AC-4） |

### 9.4 major 变更流程（M2 的至多一次）

1. **改声明 / 改实现**（工作区改动，**不提交基线刷新**）。
2. **显式刷新**：`--update-baseline --reason "<理由>"` / `--update-expected --reason "<理由>"`——**不带 `--reason` 一律拒绝且不落盘**（M0 修好的门，M1 沿用，M2 沿用**且不得放宽**）。
3. **提交信息写明理由**——**基线刷新的提交**正文必须写清改了什么、为什么。
4. **反向验证**：喂一份改坏的临时基线给工具，断言退出码非 0。
5. **同笔提交**（ADR-077 新增的纪律）：刷了基线**必须与这次改动同笔提交**——**git 背书守卫会把"改了没提交"当场拦下**。

> **"顺手刷新"是明令禁止的**。M2 计划内只有一次**新增键**的显式刷新（`replay:` 事件）——**那不是 major 变更**。**M2-C1 预留一次，不到不许用**。

### 12.2 提交约定（沿用 `AGENTS.md`）

- **标题** `类型：主题`，类型用固定表（**不临时造新类型**）。M2 预计用到：**新功能**（三个系统 · 总线 · 存储）· **修复**（审查发现）· **文档**（spec / plan / ADR）· **测试**（门判据与转录表）· **重构**（总线增强）· **性能**（千局基准）· **格式**。
- **破坏性改动**在类型后加感叹号——判据：**会不会让旧录像、旧存档或既有调用方失效**。
  - **新增 `replay:` 事件** = **不破坏**（既有事件与命令一字未改；旧消费方按"未注册的事件类型"处理——NFR-9 明写容错）→ 不加感叹号。
  - **契约基线刷新** = **破坏性**（基线换了 = 比对基准换了）→ `新功能!：`。
  - **`bus/` 独立基线首次生成** = **破坏性**（多了一份比对基准）→ `新功能!：`。
  - **`replay` / `inspect` 两个子命令从占位变成真跑** = **破坏性**（旧调用方若依赖"占位即报错"，行为变了）→ `新功能!：`。
  - **存储适配器与总线增强** = 不破坏既有调用方 → 不加感叹号。
- **正文写"改了什么、为什么"**，用中文。
- **一次提交 = 一个逻辑改动**；**格式化与逻辑改动分开提交**；**纯文档提交与代码提交不混提**。
- **基线刷新的提交**：正文必须写明**理由**（与 `--reason` 一致），**且不带 `--reason` 的刷新一律拒绝**。
