### 1.2 M7 的批次与分支

- **一条链**：`feature/m7-batch-a` → `b` → `c` → `d`。
- **每批一提交（或几笔）**，**阶段提交逐笔留在历史里**——要回滚就按阶段哈希回滚。
- **收官**：一批 `--no-ff` 合并进 `master` → **再回填哈希**（先合并、再回填）。

### 1.3 M7 为什么这么排（**四句**）

1. **先门面，后外壳**——**门面是"外置"这条纪律的载体**：**外壳若先写**，它会顺手 import 内部模块（近路最省事）→ 事后收紧纪律就得重写。**先把门面立住**，外壳只能从门面拿东西。
2. **配置先于外壳**——**配置是纯逻辑**（`tomllib` · 无 Qt · 无头可测），**先把最容易测的部分测掉**，别把无头可测的东西塞进要起窗口的阶段。
3. **画笔先于外壳**——画笔吃的是**现成的 `FrameModel`**（纯数据）→ **假画笔即可测**（不弹真窗口 · NFR-7-6）。
4. **打包放最后**——PySide6 的 PyInstaller 坑要在**前面都稳了**之后才值得踩（M6 的 tkinter 坑同类）。

## 2. 阶段通用模板

每个阶段：**先写清判据 → 实现 → 机检 → 质量门 → 提交**。

- **判据先写**：门判据的机检用例**要在实现之前**把断言写出来（哪怕先红）。
- **不许动的东西**：内核 / 规则 / 契约 / 事件基线 / `TerminalRenderer` 的既有行为 / `GraphicsRenderer` 的既有行为。
- **无头优先**：**每一阶段的机检都不许起真窗口**（CI 没有显示器 · NFR-7-6）。
- **反向验证**：每阶段的机检都要**改坏一次看它红**，再**精确还原**。
- **提交**：一次一个逻辑改动；**格式化单独一笔**。

### 6.4 回滚点

每个阶段提交都是回滚点；**门红了就按阶段哈希回滚**，不靠手工改。

### 6.5 不许做的事

- 不许改内核 / 规则 / 契约 / 事件基线。
- 不许在 Qt 层里 import 内部模块（**只 import 门面**）。
- 不许在 Qt 层长出第二套规则（画面一切来自 `FrameModel`）。
- 不许在 Qt 输入桥里重写 DAS / ARR / 命令翻译。
- 不许用 `QTimer` 接管游戏循环（**节拍只有一个主人**）。
- 不许让面板每帧重排（**按时间节流**）。
- 不许把 `TerminalRenderer` 与 `GraphicsRenderer` 的既有行为改掉。
- 不许用"窗口能打开"充当"能玩"的判据。

## 7. 风险与应急

- **PySide6 没装 / 没显示器** → `tetris qt` 明确报错 + 安装提示（**核心与终端版不受影响**）。
- **exe 体积暴涨** → Qt exe **单独发**（核心 wheel / sdist 不含它）。
- **事件流拖死主线程** → 面板**按时间节流**（NFR-7-2）。
- **高 DPI 棋盘错位** → 格子尺寸取整 + `devicePixelRatio` 校正（S3 实测）。
- **手感漂** → 输入逻辑整套复用 `KeyboardInput`。
- **范围蔓延**（想加音效 / 皮肤 / 装卸系统 / 录像回放）→ 记进「未决」，**不在 M7 做**。
